# 주인공 스프라이트 v1

- player-character.png: 투명 PNG, 2048×6144, 8열×24행, 칸 256×256. 캐릭터 109프레임.
- player-parry-fx.png: 투명 PNG, 1024×512, 4열×2행. 잔상 4프레임, 성공 섬광 3프레임.
- player-sprites.json: 실제 이미지 좌표, pico2d용 하단 원점 좌표, 재생 속도·반복·프레임별 시간·발 기준점·총구 추정 좌표.
- preview-contact.png: 밝은 배경의 확인용 이미지. 위부터 대기, 수평 달리기, 위 조준 점프, 웅크린 이동 사격, 죽기, 패링 시도. 게임용 투명 시트는 위 두 PNG.
- prompts.txt: 내장 image_gen에 전달한 생성·수정 프롬프트.
- source/: 내장 image_gen 원본. 최종 시트는 원본에서 프레임을 추출해 머리 크기와 기준점을 맞춰 재배치.

캐릭터 행 순서 (0부터):
0 대기 기본 / 1 대기 수평 / 2 대기 위 / 3 달리기 기본 / 4 달리기 수평 / 5 달리기 대각선
6~9 점프 상승 기본·수평·위·대각선 / 10~13 낙하 기본·수평·위·대각선
14 웅크리기 기본 / 15 웅크리기 수평 / 16 웅크린 이동 기본 / 17 웅크린 이동 수평
18 피격 / 19 죽기 / 20 패링 시도 / 21 패링 성공 / 22~23 개별 사격 반동 포즈

행22~23은 순서대로 재생하는 애니메이션이 아님. JSON의 recoil_animations에서 해당 자세 하나를 골라 0.05초 사용.
달리기 대각선 반동은 양발 접지 단계에서 같은 포즈를 공유. 실패 패링은 낙하 동작으로 전환하므로 별도 실패 반동 없음.
패링 시도는 0.04초씩 4장, 총0.16초. 성공은 즉시 시도 동작을 중단해 성공 반동으로 전환.
성공 반동 후 상승 속도가 양수이면 점프 상승, 0이하이면 낙하로 연결. 상승 이동은 게임 물리가 담당.
피격은 0.125초, 깜빡임은 이미지에 넣지 않음. 죽기는 반복 없이 마지막 프레임 유지.

셀 전체를 36×56으로 찌그러뜨리지 말 것. JSON render_reference의 동일 배율을 적용하고 foot_anchor를 플레이어 하단에 맞출 것.
충돌 상자는 기존 게임의 36×56 / 웅크리기36×28을 사용. 이 작업에서는 게임 코드를 변경하지 않음.

검수 한계:
- 달리기의 접지·통과·상승 단계와 반 주기 반복은 포함했지만, 생성 이미지의 좌우 보폭 및 팔·다리 교차는 수학적으로 정확한 대칭을 보장하지 않음.
- 총구 좌표는 실루엣에서 자동 추정한 값. 실제 탄환 발사 위치에 연결하기 전 프레임별 조정 필요.
- 머리색은 #F8F4E8을 목표로 생성했으며 실제 픽셀은 연필 질감과 작은 색차를 포함.
- 머리 크기를 정렬했지만 일부 동작에서 팔다리 길이와 선의 농도에 차이가 남아 있음.
