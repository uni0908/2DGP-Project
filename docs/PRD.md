# Doodle Wars PRD

- 기준 기획서: [doodle_wars_plan.pdf](../Slides/doodle_wars_plan.pdf)
- 개발 환경: Python / pico2d
- 문서 상태: 초기 요구사항 정리
- 목적: 게임 전체 요구사항을 공유하고, 아래 개발 단계를 하나씩 구현·확인한다.

이 문서는 기획서의 확정 규칙과 미정 항목을 정리한다. 개발 단계와 완료 조건은 구현을 위해 추가한 작업 기준이다. 미정인 값은 임의로 확정하지 않는다. 프로토타입에 임시 값이 필요하면 임시 값임을 기록하고 변경하기 쉽게 관리한다.

## 1. 게임 개요

| 항목 | 요구사항 |
| --- | --- |
| 제목 | Doodle Wars |
| 장르 | 1인용 2D 횡스크롤 액션 슈팅 / 보스전 중심 액션 |
| 배경 | 연필로 그린 공책 속 낙서 세계에 색연필 외계인이 침입한다. |
| 목표 | 총과 아이템으로 외계인을 물리치고, 세 번째 스테이지의 최종 UFO 보스를 처치한다. |
| 시각 스타일 | 손으로 그린 듯한 연필·색연필 드로잉 |
| 참고 게임 | 컵헤드의 패링 방식과 보스 공격 패턴 |
| 핵심 재미 | 패링으로 자원을 얻고, 낙서와 지우개로 전투 지형을 직접 구성하며 보스 패턴을 공략한다. |

낙서는 방어물인 동시에 이동 발판이며, 자신의 사격을 방해할 수도 있다. 플레이어는 낙서를 언제 만들고 언제 지울지 판단해야 한다. 연필 낙서는 지울 수 있지만 색연필 외계인은 지울 수 없다는 시각적 규칙을 유지한다.

## 2. 전체 진행과 상태 유지

진행 순서는 `횡스크롤 1 → 보스 1 → 횡스크롤 2 → 보스 2 → 횡스크롤 3 → 최종 UFO 보스`다.

- 스테이지는 총 3개이며, 중간 보스 2종과 최종 보스 1종을 구현한다.
- 횡스크롤 구간은 왼쪽에서 오른쪽으로 진행하며, 배경과 지형은 오른쪽에서 왼쪽으로 스크롤한다.
- 각 횡스크롤 구간이 끝나면 고정 화면 보스전으로 전환한다.
- 보스전은 기본적으로 바닥과 보스만 있는 단순한 공간에서 시작한다. 플레이어가 낙서로 전장을 구성한다.
- 체력과 보유 아이템은 구간 전환 후에도 유지한다. 보스전 진입 시 체력을 자동 회복하지 않는다.
- 시작 목숨은 5개다. 목숨은 별도 재도전 횟수가 아닌 체력 단위이며, 적의 공격에 피격될 때마다 1개 감소한다.
- 목숨이 0이면 게임 오버다. 최종 UFO 보스를 처치하면 클리어한다.
- 게임 오버 후 재시작 방식과 시작·클리어 화면의 상세 구성은 미정이다.

## 3. 기능 요구사항

### 3.1 플레이어와 기본 전투

- 플레이어는 좌우로 이동하고 스페이스바로 점프한다.
- 기본 무기는 총이며, 원거리 투사체로 공격한다. 기본 총격은 아이템을 소비하지 않는다.
- 패링할 수 없는 공격은 이동, 점프 또는 낙서 엄폐물로 회피한다.
- 이동 속도, 점프 높이, 총격 간격 및 스페이스바 외 조작키는 미정이다.

#### 추가 조작: 웅크리기

사용자 요청으로 아래 방향키를 누르는 동안 웅크리는 동작을 추가한다. 다음 세부 수치는 임시 설정이다.

- 지상에서 높이를 56 → 28픽셀로 줄이고 발 위치는 유지한다. 충돌·피격·그리기 모두 현재 높이를 사용한다.
- 웅크린 이동 속도는 130픽셀/초로 기본의 절반이며, 웅크리는 동안 점프는 하지 않는다.
- 공중에서 아래를 눌러도 즉시 자세를 바꾸지 않고, 착지 후 누르고 있으면 웅크린다. 발판에서 떨어지면 현재 자세로 낙하한다.
- 아래 키를 떼거나 포커스를 잃으면 일어나기를 시도한다. 서 있는 몸이 낙서와 겹치면 웅크림을 유지하고, 공간이 확보되면 자동으로 일어난다.
- 사격·지우개 총구는 낮아진 중심 높이를 따른다. 낙서 중심이 바닥 아래로 내려가는 경우에는 바닥에 맞게 생성 높이를 올려 웅크린 상태에서도 생성할 수 있다.
- 총 29개 회귀 테스트 통과. 발 위치 유지, 키 해제, 높은 탄환 회피와 낮은 탄환 피격, 낮은 천장 아래 일어나기 방지, 이동 속도·점프 제한, 착지 후 자세를 확인했다.
- 실제 SDL 아래키 입력·해제로 웅크리기·복귀, 웅크린 낙서 생성, 렌더링·종료를 확인했다. 적 총알도 충분히 낮으면 맞으므로 모든 공격을 피하는 동작은 아니다.

### 3.2 패링

- 패링 가능한 공격의 타이밍에 맞춰 스페이스바를 입력하면 공격을 방어하고 대응 아이템을 얻는다.
- 지상의 첫 스페이스바 입력은 점프만 한다. 짧게 누르면 낮게, 길게 누르면 높게 뛰고, 공중에서 키를 떼었다 다시 누를 때만 짧은 패링 판정을 활성화한다.
- 패링은 덤블링이나 발 위치에 의존하지 않고 몸통 주변을 기준으로 한다. 활성 중에는 몸통을 분홍색으로 표시한다. 덤블링 애니메이션은 현재 구현 범위에 포함하지 않는다.
- 공중 패링 성공 시 다시 도약한다. 이후 다른 패링 가능한 공격에 연속 패링할 수 있다.
- 접촉만으로는 패링되지 않는다. 패링에 실패한 상태로 공격에 닿으면 피격된다.
- 분홍색 패링 공격은 낙서 아이템을, 하늘색 패링 공격은 지우개 아이템을 제공한다.
- 일반 공격은 패링할 수 없다. 공격 색상으로 패링 가능 여부와 보상 종류를 구분한다.
- 보스전에서도 패링으로 아이템을 보충할 수 있다.
- 패링 판정의 허용 시간과 판정 범위는 미정이다.

### 3.3 낙서 생성과 충돌

- 낙서 아이템을 사용하면 바라보는 방향 바로 앞에 선이 뒤엉킨 둥근 낙서 덩어리를 생성한다.
- 생성 위치는 플레이어의 위치와 높이를 기준으로 한다. 점프 중에도 생성할 수 있다.
- 공중에 생성된 낙서는 중력 없이 생성 위치에 고정된다.
- 플레이어가 아래에서 위로 점프하면 낙서를 통과하고, 내려올 때 윗면에 착지한다.
- 낙서의 옆면은 막혀 있어 플레이어가 통과할 수 없다.
- 낙서는 플레이어의 총격과 적 투사체를 막는다.
- 일정 피해를 받으면 파괴된다. 보스의 특정 공격은 모든 낙서를 한 번에 파괴한다.
- 밟고 있던 낙서가 파괴되면 플레이어는 아래로 떨어진다.
- 사용 시 보유 수량이 1개 감소한다. 설치 개수 제한과 재사용 대기시간은 없다.
- 크기, 생성 거리·가능 범위, 내구도와 구체적인 피해·파괴 판정 기준은 미정이다.
- 플레이어·기존 낙서와 겹쳐 생성되는 상황 및 맵 경계의 생성 처리도 구현 전에 결정한다.

### 3.4 지우개

- `D`로 지우개 아이템을 사용하면 바라보는 방향으로 수평 투척한다.
- 아래 방향키를 누른 채 `D`를 누르면 발밑으로 수직 투척한다. 웅크림과 함께 사용할 수 있고 공중에서도 아래 투척이 가능하다.
- 단, 일반 바닥에 발이 닿은 상태에서는 아래키를 웅크리기로 해석하고 D도 바라보는 방향으로 수평 투척한다. 발판 위 또는 공중처럼 발이 바닥보다 높을 때만 아래+D로 아래 투척한다. 지상에서 지우개가 즉시 바닥에 닿아 사라지는 입력 충돌을 방지한다.
- 아래 투척도 처음 닿은 낙서 하나만 제거하고 수량 1개를 소모한다. 일반 바닥은 지울 수 없으며, 바닥에 도달하면 지우개만 소멸한다. 빗나가도 수량은 반환하지 않는다.
- 처음 닿은 낙서 1개를 제거한다.
- 외계인과 보스는 지울 수 없으며 피해도 주지 않는다.
- 사용 시 보유 수량이 1개 감소한다. 재사용 대기시간은 없다.
- 사격 경로를 막는 자신의 낙서를 제거하여 다시 공격할 수 있어야 한다.
- 투척 속도, 사거리, 소멸 조건은 미정이다.

추가 구현 기록: 아래 투척도 임시 속도 520픽셀/초, 최대 거리 700픽셀을 사용한다. 플레이어 중심에서 아래로 이동하며 가장 먼저 만나는 낙서만 제거한다. 총 33개 회귀 테스트에서 밟은 발판 제거·낙하, 아래 낙서의 보존, 측면 낙서 무시, 바닥 소멸과 수량 부족 처리를 확인했다.

지상 웅크림 입력 충돌 수정 후 전체 61개 회귀 테스트를 통과했다. 웅크린 좌우 수평 투척과 실제 SDL 아래키+D로 앞 낙서 제거를 확인했으며, 발판·공중 아래 투척은 유지한다.

### 3.5 아이템과 자원 관리

| 아이템 | 획득 방법 | 효과 |
| --- | --- | --- |
| 낙서 | 분홍색 공격 패링 성공 | 낙서 지형 생성 |
| 지우개 | 하늘색 공격 패링 성공 | 처음 닿은 낙서 1개 제거 |
| 1회용 방어막 | 횡스크롤 맵에서 직접 획득 | 플레이어를 감싸는 원이 생성되며, 공격을 1회 막으면 사라짐 |
| 연사 | 횡스크롤 맵에서 직접 획득 | 기본 총의 발사 속도 증가 |
| 폭탄 | 횡스크롤 맵에서 직접 획득 | 발사하면 직선으로 날아가는 공격 아이템 |

- 횡스크롤 구간에서 확보한 자원은 보스전까지 이어진다.
- 플레이어는 회피와 패링 중 무엇을 택할지, 보유 자원을 언제 사용할지 판단한다.
- 보유 수량이 없는 아이템은 사용할 수 없고, 수량은 음수가 되지 않는다. 이는 구현 시 적용할 기본 자원 보호 조건이다.
- 초기 보유 수량, 획득당 지급 수량과 최대 보유량은 미정이다.
- 연사의 지속시간·중첩 여부, 폭탄의 피해량·폭발 범위·보유량은 추후 확정한다.
- 방어막 중복 획득과 구간 전환 시 일시 효과 유지 여부는 미정이다.

### 3.6 일반 적과 횡스크롤 구간

- 일반 적과 공격을 배치하고, 플레이어가 총격으로 적을 처치할 수 있게 한다.
- 일반 공격과 패링 가능한 공격을 구분한다.
- 구간 중 아이템을 획득하고 체력을 보존하는 과정이 이후 보스전 난이도에 영향을 준다.
- 스테이지 길이, 일반 적 종류·배치·체력·공격 주기와 스크롤 세부 방식은 미정이다.

### 3.7 보스

- 보스는 일정한 규칙에 따라 공격을 반복한다. 플레이어가 패턴을 관찰하고 대응법을 익힐 수 있어야 한다.
- 일부 패턴에는 낙서 생성 또는 지우개 제거가 반드시 필요하다.
- 특정 위치에서 정해진 버튼만 누르는 방식으로 공략을 강제하지 않는다.
- 보스전 중 패링 가능한 공격을 제공하여 자원 보충 기회를 만든다.
- 중간 보스 2종의 외형, 세부 패턴, 페이즈는 미정이다.
- 최종 보스는 색연필로 그려진 거대 UFO다. 보스전 시작 시 화면 오른쪽에 위치한다.
- 최종 보스의 체력이 절반 이하가 되면 위쪽으로 이동하며 두 번째 페이즈를 시작한다.
- 최종 보스 처치 시 연기를 내뿜으며 아래로 추락하는 연출을 구현한다.

아래 공격 유형은 기획서의 후보이며, 모든 보스에 전부 넣는 확정 목록은 아니다.

| 공격 후보           | 기본 구상                         | 대응 방향                       |
| ------------------- | --------------------------------- | ------------------------------- |
| 일반 탄막           | 여러 발의 투사체 발사             | 이동, 점프, 엄폐물 생성         |
| 수평 공격           | 일정 높이의 넓은 범위 공격        | 엄폐물 설치, 발판으로 높이 변경 |
| 공중 공격           | 높은 위치에서 아래쪽으로 공격     | 공중 낙서 활용, 이동 경로 변경  |
| 패링 가능 공격      | 보상별 색상의 투사체              | 패링으로 자원 보충              |
| 지형 조작 필수 공격 | 낙서 생성 또는 제거가 필요한 공격 | 낙서·지우개 사용               |
| 전체 낙서 파괴 공격 | 설치된 모든 낙서 파괴             | 자원 관리, 필요한 지형 재생성   |

패턴 수·순서·속도·피해량과 보스 체력은 프로토타입 및 플레이테스트 후 확정한다. 아이템 필수 패턴에서 자원이 부족할 때의 보충 기회와 진행 가능 여부도 검증한다.

#### 추가 보스 패턴: 방어와 반격의 전환

지우개를 전투 중 자연스럽게 사용하도록, 낙서가 방패에서 장애물로 바뀌는 상황을 만든다. 사용자와 논의해 추가한 설계이며, 6단계의 첫 보스 프로토타입에 아래 흐름을 구현했다.

1. **공격 구간:** 보스가 탄막을 발사한다. 플레이어는 낙서를 만들어 엄폐하며 공격을 막는다.
2. **휴식 구간:** 낮은 탄막의 새 발사는 멈추고, 좁은 상단 범위에서 랜덤 높이의 일반탄을 빠르게 한 발씩 발사한다. 기존 탄은 지우지 않는다. 발판 위에 머무르기보다 아래로 내려와 반격하도록 유도한다.
3. **반격 구간:** 방어에 사용한 낙서가 플레이어의 사격 경로도 막는다. 지우개로 낙서를 제거해 보스를 공격할 기회를 확보한다. 별도 약점은 없으며 모든 상태에서 몸 전체를 공격할 수 있다.
4. **반복:** 반격 시간이 끝나면 다시 공격 구간으로 전환한다. 남길 낙서와 지울 낙서, 사용 시점은 플레이어가 판단한다.

핵심은 “아까는 방패였는데 지금은 방해물”이 되는 것이다. 낙서 없이 버티거나 우회 사격하는 대응도 허용한다. 약점 노출 설계는 폐기하고, 정량 발사·상단 사격 휴식을 반복하며 항상 현재 몸 전체에 피해를 줄 수 있도록 한다. 별도 예고선·카운트다운·예고 대기는 제거하고, 향후 적 애니메이션으로 동작 전환을 표현한다. 발사량·휴식 시간·자원 보충 방식은 플레이테스트로 조정한다.

#### 추가 보스 패턴 후보: 이동 경로 확보

- 보스 공격을 피하려고 이동할 때, 플레이어가 이전에 설치한 낙서가 옆길을 막는 상황을 만든다.
- 지우개로 방해되는 낙서를 제거해 이동 경로를 확보한다.
- 피할 방향과 공격 도달을 미리 알 수 있게 예고하고, 지우개 투척·낙서 제거·이동에 필요한 시간을 확보한다. 구체적인 공격 형태와 예고 시간은 프로토타입에서 정한다.

#### 추가 보스 패턴 후보: 발판 삭제로 낙하 회피

- 보스가 플레이어가 서 있는 발판 높이를 노리는 공격을 예고한다.
- 플레이어는 `아래 방향키 + D`로 밟고 있는 낙서를 지워 아래로 떨어지며 공격을 피할 수 있다.
- 현재 구현된 아래 지우개 투척을 활용한다. 삭제 후 낙하 시간과 착지 공간을 고려하고, 일반 바닥은 지워지지 않는 규칙을 유지한다.
- 발판에서 뛰어내리는 등 다른 회피법도 검토한다. 자원이 없을 때 진행이 막히는지, 지우개 수량과 보충 기회가 적절한지도 함께 검증한다.

위 후보들은 6단계 보스 1종의 핵심 전투 검증에서 적용 가능성을 확인하고, 사용할 보스와 최종 패턴 구성은 이후 확정한다.

#### 보스2 기획 아이디어: 세로 맵의 상승·하강 전투

사용자 제안으로 보스2는 세로로 긴 맵에서 전투한다. 플레이어는 낙서 발판을 계속 만들어 올라가고, 다시 내려오는 행동을 반복한다. 보스2도 맵의 위아래를 이동한다. 보스1의 좌우 사격·엄폐 중심 전투와 다른 경험을 목표로 한다. 현재는 기획만 기록하며 맵·카메라·보스2 코드는 아직 구현하지 않는다.

기본 흐름은 아래를 프로토타입 후보로 삼는다. 구체적인 공격과 순서·수치는 아직 확정하지 않는다.

1. **상승 구간:** 보스2가 위로 이동한다. 플레이어는 공중 낙서 발판을 만들어 올라가며 따라간다. 아래쪽을 위협하는 공격으로 상승을 유도하는 방안을 검토한다.
2. **높은 곳 전투:** 보스가 일정 높이에 머무르며 플레이어에게 공격 기회를 준다.
3. **하강 구간:** 위쪽을 덮는 공격 등으로 하강을 유도한다. 발판 옆으로 내려오거나 아래 방향키+D로 발판을 지워 빠르게 낙하하는 선택을 제공한다.
4. **아래쪽 전투:** 다시 반격하고 자원을 보충할 기회를 제공한 뒤 상승 흐름으로 이어간다.

- 낙서는 상승 경로이면서 하강 시 제거할 수 있는 지형이다. 지우개는 발판 삭제와 빠른 낙하에 활용한다. 지우개 사용 시 낙서 회수 기능은 별도 논의 사항이며, 이 기획으로 구현을 확정하지 않는다.
- 카메라는 플레이어의 높이를 따라가는 방식을 우선 검토한다. 화면 밖 보스의 방향과 화면 밖에서 들어오는 공격을 알 수 있게 표시하는 방안도 검토한다.
- 먼저 작은 세로 테스트 맵에서 낙서 생성·착지로 연속 상승하는 조작과 발판 삭제·낙하 조작이 편한지 확인한 뒤 보스2를 연결한다.
- 보스전 중 낙서·지우개를 충분히 보충할 기회가 필요하다. 자원이 부족하면 상승이나 하강 진행이 막히는지, 안전하게 다시 시도할 수 있는지 검증한다.
- 맵 높이, 카메라 추적·경계, 보스 이동 범위·속도, 상승·하강 유도 공격, 반격 시간, 자원 보충 방식·수량, 낙하 중 피격·바닥 처리와 화면 밖 공격 표현은 미정이다.
- 보스2 전용 행동은 보스1과 분리한다. 현재 보스1 구현을 이 아이디어에 맞춰 변경하지 않는다.

### 3.8 그래픽, UI, 사운드

#### 5단계 임시 설정과 검증 기록

이번 검증에서는 4단계의 테스트 적 상하 이동을 끄고 발사 속도를 낮췄다. 앞 단계의 수치는 당시 검증 기록이며, 현재 테스트 설정은 아래를 따른다. 정식 보스 행동은 6단계에서 설계한다.

- 테스트 적은 오른쪽 x=864, 중심 y=170에 고정한다. 크기 144 × 112와 체력 30은 유지한다.
- 탄환은 바닥에서 90픽셀 위인 y=170에서 왼쪽으로 발사한다. 일반탄 → 분홍탄 → 하늘탄을 1.2초 간격으로 반복하며, 탄속은 기존 240픽셀/초다. 가변 점프 도입으로 짧게 뛰고 바로 위 탄을 패링하는 연습을 할 수 있도록 이전에 올렸던 y=230을 되돌렸다.
- 가변 점프: 스페이스바를 유지하면 초기 속도 620픽셀/초와 중력 1800픽셀/초²로 최대 약 107픽셀 상승한다. 상승 중 키를 놓으면 남은 상승 속도를 최대 180픽셀/초로 제한한다. 0.016초 뒤 놓는 짧은 점프는 약 19픽셀 상승한다. 더 늦게 놓을수록 높이 뛰며, 하강 중 해제로 다시 상승하지 않는다.
- 일반탄은 주황색 12 × 6픽셀, 패링 가능 탄은 분홍·하늘색 20 × 14픽셀로 표시한다. 발사 순서는 재시작하면 일반탄부터 초기화한다.
- 첫 지상 입력은 점프만 한다. 공중에서 스페이스바를 떼었다 다시 누르면 0.16초 동안 몸통 주변의 패링 판정을 활성화한다. 범위는 몸 경계에서 위쪽 24픽셀, 좌우 16픽셀, 아래쪽 12픽셀이다. 활성 중 몸통 전체를 분홍색으로 표시하며, 덤블링·발 회전과 판정을 연결하지 않는다.
- 활성 시간 안에 색상 탄이 들어오면 패링한다. 실패한 공중 재입력 자체는 상승 속도를 늘리지 않으며, 일반 더블 점프는 없다. 계속 누르고 있거나 OS 반복 입력이 와도 시간을 갱신하지 않는다.
- 분홍탄 패링 시 낙서 1개, 하늘탄 패링 시 지우개 1개를 즉시 지급한다. 보상은 해당 탄환을 막은 순간에 한 번만 지급하며, 임시 최대 보유량은 두지 않는다.
- 성공한 탄은 피해 없이 소멸하고, 플레이어의 수직 속도를 620픽셀/초로 재설정해 도약한다. 이 성공 도약은 키를 떼어도 짧아지지 않는다. 한 번의 입력은 탄환 하나만 패링하고 판정을 닫으며, 연속 성공에는 재입력이 필요하다.
- 일반탄과 패링이 꺼진 상태의 접촉은 기존 피격 규칙을 따른다. 첫 점프만 하거나 활성 시간이 끝난 뒤 맞으면 피해를 받는다. 피격 시 남은 패링 판정을 취소한다. 피격 후 1초 무적은 유지한다.
- 낙서가 먼저 막은 탄은 낙서에 피해를 주고 사라지며 보상은 없다. 웅크린 상태는 기존 점프 제한과 함께 패링도 시작하지 않는다. 포커스를 잃으면 활성 판정을 취소한다.
- HUD에 색상별 보상과 조작법을 표시한다.
- 착지·포커스 상실·재시작 시 활성 패링을 취소한다. 성공 안내는 0.8초 동안 표시하고 초기 자원은 재시작 때 복원한다.
- 공용 Python 3.13.7 환경에서 전체 47개 회귀 테스트를 통과했다. 짧은·중간·긴 점프 높이, 첫 점프 패링 불가, 공중 재입력 후 활성 시간 내 접촉, 만료 후 피격, 일반탄 피격, 연속 성공·중복 보상 방지, 성공 도약의 해제 내성, 머리 바로 위 탄의 짧은 점프 패링, 낙서 차단, 착지·포커스 취소를 검증했다.
- 실제 SDL 입력으로 짧게 점프 → 해제 → 공중 재입력 → y=170 탄 패링·보상·재도약을 확인했다. 판정 활성 중 분홍 몸통을 그리는 실행 경로와 정상 종료도 확인했다. 수동 조작감과 활성 시간은 플레이테스트 후 조정한다.

#### 보스1 공격 명칭과 패턴 구성

현재 제작 중인 적은 **보스1**이다. **탄막 공격 → 일반 공격 → 유도탄 공격 → 레이저 공격** 순서로 네 패턴을 반복한다. 보스마다 별도 패턴을 둘 수 있게 전용 클래스로 분리한다. 자원 부족·밸런스 검증은 남아 있으므로 6단계 전체 완료는 아니다.

1. **탄막 공격:** 다층 낙서 방어 → 낮아진 보스와 상단 사격 휴식 → 낙서 제거 후 반격. 구현.
2. **일반 공격:** 상하 왕복 중 일반탄 3발 → 멈춤 → 패링탄 단독 발사 → 회피·도약 여유 시간. 구현.
3. **유도탄 공격:** 일반 유도탄을 낙서로 막은 뒤 단독 패링 유도탄에 대응한다. 구현.
4. **레이저 공격:** 얇은 가로 레이저가 아래→위→아래로 화면 대부분을 쓸며 완전히 통과한 낙서를 전부 제거한다. 구현.

별도 후보였던 패링 탄 연속 발사는 일반 공격의 단독 패링탄으로 통합했다. 기존 바닥 쓸기·발판 높이 저격은 현재 네 패턴에 포함하지 않는 미구현 후보로 남겨둔다.

현재 1번은 `0.45초 간격으로 6묶음 발사 → 랜덤 상단 단발을 쏘는 휴식 4초 → 공격`을 반복하며, 시작부터 별도 예고 대기 없이 공격한다. 공격 구간은 묶음당 6발로 총 36발을 쏘고, 마지막 발사 후 간격을 포함해 2.7초다. 휴식의 상단 사격은 별도다. 수치는 모두 임시 값이다. 향후 네 패턴을 1→2→3→4 순서로 연결하는 것을 기본안으로 삼는다.

- `boss1.py`의 `Boss1`이 보스1 전용 상태와 전환을 관리한다. `boss.py`의 `Boss`는 기존 참조의 호환 이름이다. 플레이 화면은 `Boss1`을 직접 생성하며, 다른 보스에 이 패턴을 자동 적용하지 않는다. 기존 `enemy.py`의 `TestEnemy`는 기초 테스트 적으로 남겨둔다.
- 보스는 x=864, 기본 중심 y=136, 크기 144×112, 체력 30이다. 휴식에는 발 위치 y=80을 유지하고 높이를 절반인 56으로 줄인다. 표시·실제 피격 범위 모두 y=80~136이 되며, 위에 올라가 쏘면 낮아진 몸을 빗나갈 수 있다. 휴식 후에는 원래 높이로 복귀한다.
- 휴식은 웅크려 기를 모으는 모습으로 색상과 주변 테두리를 바꿔 표시한다. 약점은 없고, 항상 현재 몸 전체에 피해가 들어간다.
- 공격 중 0.45초마다 높이 y=88·104·120·136·152·168의 일반탄 6발을 발사한다. 탄속은 200픽셀/초, 각 탄 크기는 12×14픽셀이며 패링 보상은 없다. 각 탄은 처음 닿은 낙서 하나에 피해 1을 주고 사라진다.
- 세로 약 96픽셀에 걸친 탄막으로, 낙서 한 층만 세우면 서 있는 플레이어의 머리 쪽이 노출된다. 2층은 지상의 서 있는 플레이어를, 3층은 더 높은 위치까지 가리는 것을 목표로 한다. 웅크리기·이동·점프 회피를 금지하지 않으므로 모든 상황에서 3층을 강제하지는 않는다. 낙서는 점프 중 S로 높이를 달리해 쌓을 수 있으며, 기존 겹침 금지 규칙은 유지한다.
- 상태 전환과 보스 처치로 이미 발사된 탄을 강제 삭제하지 않는다. 적·아군 총알은 기존 충돌 또는 화면 이탈 조건까지 계속 움직인다. 재시작·장면 종료 시 월드 정리는 별개다. 따라서 휴식 초반에는 이전에 발사된 낮은 탄을 계속 피하거나 막아야 한다.
- 상단은 최저 높이를 유지하며 범위 폭을 절반으로 축소했다. 이전 y=152~312에서 현재 y=152~232 안의 연속 랜덤 높이를 골라 한 번에 일반탄 한 발을 발사한다. 간격도 0.08~0.14초 사이에서 랜덤으로 정하고, 탄속은 300픽셀/초다. 세로 한 줄 동시 발사·플레이어 추적·패링탄은 없다.
- 새 상단 탄의 가장 낮은 아랫면은 y=145로, 지상 플레이어 머리 y=136보다 높다. 발판 위는 계속 위협하고 지상에서는 새 상단 탄이 머리 위로 지나간다. 아래+D로 발판을 지우거나 내려온 뒤 D로 사격 경로를 열도록 유도하지만 다른 회피법도 허용한다.
- 공격·휴식 모두 현재 몸체 전체에 들어온 플레이어 총알당 피해 1을 받는다. 약점 전용 판정과 초록 약점 표시는 없다.
- 낙서는 기존처럼 양쪽 총알을 막으므로, 보스가 쉬어도 앞의 낙서를 남기면 사격이 가로막힌다. D로 제거한 뒤 A 연사로 반격할 수 있다. 우회 사격·회피도 허용하며 지우개만 정답으로 강제하지 않는다.
- 처치 시 새 사격만 멈추고 이미 발사된 탄은 계속 움직인다. 처치·게임 오버 모두 R로 다시 시작할 수 있다.
- 전체 60개 회귀 테스트에서 예고 없는 공격·상단 사격 반복, 전환 및 처치 후 낮은 탄 포함 기존 탄 보존·자연 소멸, 좁아진 랜덤 높이·연사 빈도, 지상/발판 높이 피격 차이, 다층 방어와 휴식 피격 범위를 확인했다. 실제 SDL 창에서 즉시 공격, 상단 랜덤 단발과 범위 축소, 예고 없는 렌더링·보스 자세를 검증했다.
- 실제 SDL 창에서 낙서 방어 후 D 제거와 반격을 확인했다. 이후 네 패턴과 전체 낙서 제거까지 구현했으나 자원 부족 시 진행 가능성과 최종 난이도는 추가 검증이 필요하다.

#### 보스1 일반 공격 임시 설정과 검증

#### 보스1 유도탄 공격 임시 설정과 검증

- 세 번째 패턴의 이름은 **유도탄 공격**이다. 보스는 오른쪽에 고정된 기본 크기로 돌아오며, 일반 유도탄 2발을 0.7초 간격으로 발사한다. 발사 구간은 1.4초다.
- 일반 유도탄은 크기 20×12픽셀, 속도 150픽셀/초, 최대 회전 속도 초당 110도다. 살아 있는 플레이어 위치를 향해 완만하게 방향을 바꾸며 즉시 방향을 꺾지 않는다.
- 유도탄에는 시간 제한과 화면 밖 이탈 소멸을 적용하지 않는다. 화면 밖으로 나가도 추적할 수 있고, 보스 처치·패턴 전환으로 강제 삭제하지 않는다. 낙서에 닿으면 내구도를 1 줄이고 소멸한다. 플레이어 피격 또는 패링 충돌은 한 번 처리한 뒤 소멸한다. 재시작·장면 종료의 월드 정리는 기존대로 적용한다.
- 일반 유도탄 2발 발사 후, 기존 적 총알·유도탄이 모두 해소될 때까지 새 탄을 쏘지 않는다. 단순히 정해진 시간만 기다리고 다음 패링탄을 겹쳐 발사하지 않는다. 유도탄이 남으면 낙서로 막거나 충돌을 해소해야 다음 단계로 진행한다.
- 주변 적 투사체가 없어진 뒤 패링 가능한 유도탄을 단독으로 한 발 발사한다. 첫 방문은 분홍(낙서 +1), 다음 방문은 하늘(지우개 +1)로 번갈아 사용한다. 크기는 24×18픽셀, 속도는 120픽셀/초, 회전 속도는 초당 90도로 일반 유도탄보다 느리다.
- 패링 유도탄이 남아 있는 동안 다른 공격을 추가하지 않는다. 패링 성공·낙서 차단·플레이어 피격으로 해소되면 1초간 새 공격 없이 기다린 뒤 레이저 준비 상태로 넘어간다. 성공 후 재도약이 다음 공격과 바로 겹치지 않도록 한다.
- 일반 유도탄은 패링 불가이며 색상 유도탄만 기존 공중 재입력 패링 규칙을 따른다. 실패하면 피격·기존 무적 규칙을 적용한다. 보상 중복 지급과 동일 탄의 중복 피해를 막는다.
- `homing_missile.py`가 2차원 추적·이동 구간 충돌을 담당한다. 대각선으로 낙서를 관통하지 않도록 선분과 확장 사각형의 최초 접촉을 계산한다.
- 전체 74개 회귀 테스트 통과. 회전 제한, 목표 추적, 시간·화면 밖 유지, 낙서 및 대각선 충돌, 두 색상 보상·일반 유도탄 피격, 기존 탄 해소 대기, 단독 패링탄, 추가 1초 여유, 방문별 색상 교대와 다음 패턴 연결을 확인했다.
- 실제 SDL 창에서 유도탄 2발이 낙서에 막힌 뒤 단독 분홍 유도탄이 나오고, 스페이스바 재입력 패링·보상·재도약·회복 후 탄막 복귀를 확인했다. 지속 추적의 회피 난이도와 자원 부족 상황은 플레이테스트로 추가 조정한다. 지우개 회수는 이번 범위에 넣지 않는다.

- 발사된 레이저는 보스가 처치돼도 왕복을 계속하며, 정상 왕복 완료 또는 재시작·장면 종료 시 정리된다. 상승 후 새로 설치된 낙서도 하강 경로에 있으면 제거된다.
- 전체 80개 회귀 테스트를 통과했다. 두께·속도, 상승·하강 경계, 정상 설치 가능한 좌우·상하 끝의 낙서 전부 제거, 하강 중 새 낙서 제거, 지지 발판 삭제 후 낙하, 왼쪽 회피 공간·무적, 한 번만 발사·왕복 완료 대기·다음 패턴 전환과 보스 처치 후 레이저 유지를 확인했다.
- 실제 SDL 창에서도 다수 낙서를 화면 끝까지 배치하고 왕복 레이저로 전부 지우는 흐름, 하강 도중 추가 낙서 제거, 왼쪽에서 체력 보존과 탄막 공격 복귀를 검증했다. 최종 회피 난이도와 자원 순환은 플레이테스트로 조정한다.

### 7단계: 횡스크롤과 전체 진행 연결

구현 범위: 횡스크롤 구간, 적·아이템 배치, 보스전 전환, 상태 유지.

- [ ] 횡스크롤 구간을 진행하고 끝에서 고정 화면 보스전으로 전환한다.
- [ ] 전환 전후 체력과 보유 아이템이 같고 자동 체력 회복이 없다.
- [ ] 보스 처치 후 다음 구간으로 진행한다.
- [ ] 이전 구간의 적·투사체가 다음 구간에 잘못 남지 않는다. 낙서의 구간 전환 처리는 별도로 확정한다.

### 8단계: 나머지 콘텐츠와 아이템

구현 범위: 총 3개 스테이지, 중간 보스 2종, 최종 UFO, 방어막·연사·폭탄.

- [ ] 세 횡스크롤 구간과 각 보스전을 순서대로 진행할 수 있다.
- [ ] 맵에서 방어막·연사·폭탄을 획득하고 각각의 효과를 확인한다.
- [ ] 방어막은 공격 1회를 막은 뒤 사라진다.
- [ ] 최종 UFO는 체력 절반 이하에서 위로 이동하며 두 번째 페이즈를 시작한다.
- [ ] 최종 UFO 처치 시 추락 연출 후 클리어 상태로 전환한다.

### 9단계: 표현과 최종 점검

구현 범위: 최종 그래픽·애니메이션, UI, 사운드, 밸런스와 버그 수정.

- [ ] 연필 낙서·색연필 외계인과 패링 공격 색상을 구분할 수 있다.
- [ ] 체력과 아이템 상태를 플레이 중 확인할 수 있다.
- [ ] 첫 스테이지부터 최종 클리어까지 한 번에 플레이할 수 있다.
- [ ] 게임 오버, 연속 패링, 공중 발판 파괴, 자원 소진을 점검한다.
- [ ] 최종 조작법과 실행 방법을 README에 반영한다.

## 7. 현재 프로젝트와 작업 요청 방법

현재 파일 역할은 다음과 같다. 기능이 늘어날 때 필요한 모듈을 추가하고, 처음부터 모든 폴더를 만들지는 않는다.

```text
Project/
├─ README.md
├─ .gitignore
├─ main.py             # 실행 시작점과 게임 루프
├─ play_mode.py        # 플레이 화면의 입력·업데이트·그리기
├─ player.py           # 플레이어 동작
├─ game_world.py       # 객체 등록·업데이트·그리기와 레이어 관리
├─ doodle.py           # 고정 낙서 지형과 생성 겹침 판정
├─ eraser.py           # 지우개 수평 이동·첫 낙서 충돌·소멸
├─ bullet.py           # 진영별 수평 총알·최초 충돌·피해
├─ enemy.py            # 오른쪽 상하 왕복·연사 테스트 적
├─ assets/
│  ├─ images/
│  └─ sounds/
├─ docs/
│  └─ PRD.md
└─ Slides/             # 원본 기획서와 발표 자료
```

개발 요청 예시: **“docs/PRD.md의 1단계를 구현해줘. 미정인 값은 임시 값으로 기록하고 완료 조건까지 확인해줘.”**

완료 후 해당 단계 체크박스를 갱신하고, 채택한 임시 값과 변경된 규칙을 이 문서에 기록한다. 다음 요청에서 다음 단계를 진행한다. 매 단계마다 별도 PRD를 만들지 않는다.

## 8. 점진적 개발과 커밋 규칙

- 개발은 위 단계 순서에 따라 점진적으로 진행한다. 여러 단계의 기능을 한꺼번에 구현하지 않고, 요청받은 단계 범위에서 작업한다.
- 한 단계 안에서도 실행 창, 좌우 이동, 점프처럼 확인 가능한 작은 작업 단위로 나누어 코딩한다.
- 각 작업 단위는 `구현 → 동작 확인 → 커밋` 순서로 진행한다. 단계 전체가 끝날 때까지 변경을 모아두지 않고, 의미 있는 기능 추가나 버그 수정이 확인될 때마다 수시로 커밋한다.
- 커밋에는 해당 작업과 관련된 변경만 포함한다. 관계없는 작업을 하나의 커밋에 섞지 않는다.
- 커밋 메시지는 한글로 작성하고, 무엇을 구현하거나 수정했는지 구체적으로 적는다. 파일명이나 기술 용어는 필요하면 원문을 사용한다.
- 커밋 메시지 예시: `게임 창과 기본 루프 추가`, `플레이어 좌우 이동 구현`, `점프와 바닥 착지 구현`, `낙서 옆면 충돌 오류 수정`.
- 단계 완료 시 완료 조건을 확인하고 PRD 체크리스트와 임시 값 기록도 갱신한다. 실행 확인이 불가능한 경우에는 확인하지 못한 항목과 이유를 명시하고 완료로 표시하지 않는다.
- 로컬 커밋과 원격 저장소 푸시는 구분한다. 푸시는 별도 요청이 있을 때 진행한다.
