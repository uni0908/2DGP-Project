# Doodle Wars PRD

- 기준 기획서: [doodle_wars_plan.pdf](../Slides/doodle_wars_plan.pdf)
- 개발 환경: Python / pico2d
- 문서 상태: 초기 요구사항 정리
- 목적: 게임 전체 요구사항을 공유하고, 아래 개발 단계를 하나씩 구현·확인한다.

이 문서는 기획서의 확정 규칙과 미정 항목을 정리한다. 개발 단계와 완료 조건은 구현을 위해 추가한 작업 기준이다. 미정인 값은 임의로 확정하지 않는다. 프로토타입에 임시 값이 필요하면 임시 값임을 기록하고 변경하기 쉽게 관리한다.

## 1. 게임 개요

| 항목 | 요구사항 |
| --- | --- |
| 제목 | Doodle Wars |
| 장르 | 1인용 2D 횡스크롤 액션 슈팅 / 보스전 중심 액션 |
| 배경 | 연필로 그린 공책 속 낙서 세계에 색연필 외계인이 침입한다. |
| 목표 | 총과 아이템으로 외계인을 물리치고, 세 번째 스테이지의 최종 UFO 보스를 처치한다. |
| 시각 스타일 | 손으로 그린 듯한 연필·색연필 드로잉 |
| 참고 게임 | 컵헤드의 패링 방식과 보스 공격 패턴 |
| 핵심 재미 | 패링으로 자원을 얻고, 낙서와 지우개로 전투 지형을 직접 구성하며 보스 패턴을 공략한다. |

낙서는 방어물인 동시에 이동 발판이며, 자신의 사격을 방해할 수도 있다. 플레이어는 낙서를 언제 만들고 언제 지울지 판단해야 한다. 연필 낙서는 지울 수 있지만 색연필 외계인은 지울 수 없다는 시각적 규칙을 유지한다.

## 2. 전체 진행과 상태 유지

진행 순서는 `횡스크롤 1 → 보스 1 → 횡스크롤 2 → 보스 2 → 횡스크롤 3 → 최종 UFO 보스`다.

- 스테이지는 총 3개이며, 중간 보스 2종과 최종 보스 1종을 구현한다.
- 횡스크롤 구간은 왼쪽에서 오른쪽으로 진행하며, 배경과 지형은 오른쪽에서 왼쪽으로 스크롤한다.
- 각 횡스크롤 구간이 끝나면 고정 화면 보스전으로 전환한다.
- 보스전은 기본적으로 바닥과 보스만 있는 단순한 공간에서 시작한다. 플레이어가 낙서로 전장을 구성한다.
- 체력과 보유 아이템은 구간 전환 후에도 유지한다. 보스전 진입 시 체력을 자동 회복하지 않는다.
- 시작 목숨은 5개다. 목숨은 별도 재도전 횟수가 아닌 체력 단위이며, 적의 공격에 피격될 때마다 1개 감소한다.
- 목숨이 0이면 게임 오버다. 최종 UFO 보스를 처치하면 클리어한다.
- 게임 오버 후 재시작 방식과 시작·클리어 화면의 상세 구성은 미정이다.

## 3. 기능 요구사항

### 3.1 플레이어와 기본 전투

- 플레이어는 좌우로 이동하고 스페이스바로 점프한다.
- 기본 무기는 총이며, 원거리 투사체로 공격한다. 기본 총격은 아이템을 소비하지 않는다.
- 패링할 수 없는 공격은 이동, 점프 또는 낙서 엄폐물로 회피한다.
- 이동 속도, 점프 높이, 총격 간격 및 스페이스바 외 조작키는 미정이다.

### 3.2 패링

- 패링 가능한 공격의 타이밍에 맞춰 스페이스바를 입력하면 공격을 방어하고 대응 아이템을 얻는다.
- 지상에서 첫 점프를 할 때 또는 점프 중 스페이스바를 다시 입력할 때 패링할 수 있다.
- 공중 패링 성공 시 다시 도약한다. 이후 다른 패링 가능한 공격에 연속 패링할 수 있다.
- 접촉만으로는 패링되지 않는다. 패링에 실패한 상태로 공격에 닿으면 피격된다.
- 분홍색 패링 공격은 낙서 아이템을, 하늘색 패링 공격은 지우개 아이템을 제공한다.
- 일반 공격은 패링할 수 없다. 공격 색상으로 패링 가능 여부와 보상 종류를 구분한다.
- 보스전에서도 패링으로 아이템을 보충할 수 있다.
- 패링 판정의 허용 시간과 판정 범위는 미정이다.

### 3.3 낙서 생성과 충돌

- 낙서 아이템을 사용하면 바라보는 방향 바로 앞에 선이 뒤엉킨 둥근 낙서 덩어리를 생성한다.
- 생성 위치는 플레이어의 위치와 높이를 기준으로 한다. 점프 중에도 생성할 수 있다.
- 공중에 생성된 낙서는 중력 없이 생성 위치에 고정된다.
- 플레이어가 아래에서 위로 점프하면 낙서를 통과하고, 내려올 때 윗면에 착지한다.
- 낙서의 옆면은 막혀 있어 플레이어가 통과할 수 없다.
- 낙서는 플레이어의 총격과 적 투사체를 막는다.
- 일정 피해를 받으면 파괴된다. 보스의 특정 공격은 모든 낙서를 한 번에 파괴한다.
- 밟고 있던 낙서가 파괴되면 플레이어는 아래로 떨어진다.
- 사용 시 보유 수량이 1개 감소한다. 설치 개수 제한과 재사용 대기시간은 없다.
- 크기, 생성 거리·가능 범위, 내구도와 구체적인 피해·파괴 판정 기준은 미정이다.
- 플레이어·기존 낙서와 겹쳐 생성되는 상황 및 맵 경계의 생성 처리도 구현 전에 결정한다.

### 3.4 지우개

- 지우개 아이템을 사용하면 바라보는 방향으로 수평 투척한다.
- 처음 닿은 낙서 1개를 제거한다.
- 외계인과 보스는 지울 수 없으며 피해도 주지 않는다.
- 사용 시 보유 수량이 1개 감소한다. 재사용 대기시간은 없다.
- 사격 경로를 막는 자신의 낙서를 제거하여 다시 공격할 수 있어야 한다.
- 투척 속도, 사거리, 소멸 조건은 미정이다.

### 3.5 아이템과 자원 관리

| 아이템 | 획득 방법 | 효과 |
| --- | --- | --- |
| 낙서 | 분홍색 공격 패링 성공 | 낙서 지형 생성 |
| 지우개 | 하늘색 공격 패링 성공 | 처음 닿은 낙서 1개 제거 |
| 1회용 방어막 | 횡스크롤 맵에서 직접 획득 | 플레이어를 감싸는 원이 생성되며, 공격을 1회 막으면 사라짐 |
| 연사 | 횡스크롤 맵에서 직접 획득 | 기본 총의 발사 속도 증가 |
| 폭탄 | 횡스크롤 맵에서 직접 획득 | 발사하면 직선으로 날아가는 공격 아이템 |

- 횡스크롤 구간에서 확보한 자원은 보스전까지 이어진다.
- 플레이어는 회피와 패링 중 무엇을 택할지, 보유 자원을 언제 사용할지 판단한다.
- 보유 수량이 없는 아이템은 사용할 수 없고, 수량은 음수가 되지 않는다. 이는 구현 시 적용할 기본 자원 보호 조건이다.
- 초기 보유 수량, 획득당 지급 수량과 최대 보유량은 미정이다.
- 연사의 지속시간·중첩 여부, 폭탄의 피해량·폭발 범위·보유량은 추후 확정한다.
- 방어막 중복 획득과 구간 전환 시 일시 효과 유지 여부는 미정이다.

### 3.6 일반 적과 횡스크롤 구간

- 일반 적과 공격을 배치하고, 플레이어가 총격으로 적을 처치할 수 있게 한다.
- 일반 공격과 패링 가능한 공격을 구분한다.
- 구간 중 아이템을 획득하고 체력을 보존하는 과정이 이후 보스전 난이도에 영향을 준다.
- 스테이지 길이, 일반 적 종류·배치·체력·공격 주기와 스크롤 세부 방식은 미정이다.

### 3.7 보스

- 보스는 일정한 규칙에 따라 공격을 반복한다. 플레이어가 패턴을 관찰하고 대응법을 익힐 수 있어야 한다.
- 일부 패턴에는 낙서 생성 또는 지우개 제거가 반드시 필요하다.
- 특정 위치에서 정해진 버튼만 누르는 방식으로 공략을 강제하지 않는다.
- 보스전 중 패링 가능한 공격을 제공하여 자원 보충 기회를 만든다.
- 중간 보스 2종의 외형, 세부 패턴, 페이즈는 미정이다.
- 최종 보스는 색연필로 그려진 거대 UFO다. 보스전 시작 시 화면 오른쪽에 위치한다.
- 최종 보스의 체력이 절반 이하가 되면 위쪽으로 이동하며 두 번째 페이즈를 시작한다.
- 최종 보스 처치 시 연기를 내뿜으며 아래로 추락하는 연출을 구현한다.

아래 공격 유형은 기획서의 후보이며, 모든 보스에 전부 넣는 확정 목록은 아니다.

| 공격 후보 | 기본 구상 | 대응 방향 |
| --- | --- | --- |
| 일반 탄막 | 여러 발의 투사체 발사 | 이동, 점프, 엄폐물 생성 |
| 수평 공격 | 일정 높이의 넓은 범위 공격 | 엄폐물 설치, 발판으로 높이 변경 |
| 공중 공격 | 높은 위치에서 아래쪽으로 공격 | 공중 낙서 활용, 이동 경로 변경 |
| 패링 가능 공격 | 보상별 색상의 투사체 | 패링으로 자원 보충 |
| 지형 조작 필수 공격 | 낙서 생성 또는 제거가 필요한 공격 | 낙서·지우개 사용 |
| 전체 낙서 파괴 공격 | 설치된 모든 낙서 파괴 | 자원 관리, 필요한 지형 재생성 |

패턴 수·순서·속도·피해량과 보스 체력은 프로토타입 및 플레이테스트 후 확정한다. 아이템 필수 패턴에서 자원이 부족할 때의 보충 기회와 진행 가능 여부도 검증한다.

### 3.8 그래픽, UI, 사운드

- 연필 낙서와 색연필 외계인의 차이를 시각적으로 유지한다.
- 애니메이션 프레임을 최소화하고, 반복 배경과 코드 기반 움직임을 적극 활용한다.
- 개발용 UI에는 남은 체력과 낙서·지우개 수량을 표시하여 상태를 확인할 수 있게 한다.
- 최종 UI의 배치, 보스 체력 표시, 효과음·배경음악 목록은 별도 확정한다.
- 기능 검증 단계에서는 임시 도형·이미지를 사용할 수 있다. 이는 개발 편의를 위한 방식이며 최종 그래픽 요구사항을 대체하지 않는다.

## 4. 단계별 구현과 완료 조건

각 단계는 이전 단계가 동작하는 상태에서 진행한다. 아래 체크박스는 아직 구현 완료를 뜻하지 않는다. 단계마다 완료 조건을 확인한 뒤 체크한다.

### 1단계: 실행, 이동, 점프

구현 범위: pico2d 창, 게임 루프, 입력 처리, 플레이어 좌우 이동, 점프, 바닥 충돌.

- [x] `main.py`로 창이 열리고 종료 입력으로 정상 종료한다.
- [x] 좌우 이동과 점프가 가능하며, 착지 후 다시 점프할 수 있다.
- [x] 플레이어가 바닥을 뚫지 않고, 좌우 입력 해제 시 이동이 멈춘다.
- [x] 기본 게임 진행에는 `game_framework.py`를 추가하지 않고 현재 구조를 사용한다.

#### 1단계 임시 설정과 검증 기록

다음 값은 프로토타입용이며 최종 밸런스가 아니다. 창·바닥 값은 `play_mode.py`, 플레이어 수치는 `player.py`의 상수로 관리한다.

| 항목 | 임시 설정 |
| --- | --- |
| 창 크기 | 960 × 540 픽셀 |
| 바닥 높이 | 화면 아래에서 80 픽셀 |
| 플레이어 | 36 × 56 픽셀의 사각형, 시작 중심 x=120, 바닥 위에 배치 |
| 이동키 | 왼쪽·오른쪽 방향키, 동시 입력 시 정지 |
| 점프키 | 스페이스바, 착지 후 키를 떼었다 다시 눌러야 재점프 |
| 종료 | Escape 또는 창 닫기 |
| 이동 속도 | 260 픽셀/초 |
| 점프 초기 속도 | 620 픽셀/초 |
| 중력 | 1800 픽셀/초², 이론상 점프 높이 약 107 픽셀 |
| 시간 처리 | 경과 시간 기반 이동, 프레임 간격은 최대 0.05초로 제한 |
| 화면 경계 | 플레이어 전체가 가로 화면 안에 머물도록 제한 |

- `Player` 클래스는 위치·방향·입력·점프 상태를 관리하고, `play_mode.py`가 객체를 생성해 호출한다. 게임 월드 관리는 2단계에서 검토한다.
- 실제 pico2d/SDL 창을 생성하여 그리기 루프와 종료를 실행했다. Escape와 창 닫기 이벤트를 코드로 주입해 종료 처리를 확인했다.
- 이동·반복 키 입력·키 해제·화면 경계·입력 초기화, 점프·공중 재점프 방지·착지·착지 후 재점프·큰 시간 간격에서 바닥 관통 방지를 assertion으로 확인했다.
- 실제 SDL 포커스 상실 이벤트와 종료 이벤트를 큐에 넣어 메인 루프를 통과하는 것도 확인했다. 포커스를 잃으면 이동키 상태를 초기화한다.
- 검증 환경: 기존 수업 공용 `../.venv`의 Python 3.13.7과 pico2d 1.5.1로 실제 게임 창 실행·종료와 의존성 검사를 통과했다. 초기 실행 실패는 Python 부재가 아니라 에이전트 샌드박스의 접근 제한 때문이었다. 기존 공용 환경을 그대로 사용한다.
- 물리 키보드 조작감과 최종 그래픽은 미검증이다. 위 완료 표시는 실제 SDL 실행 및 자동 입력·상태 검증 기준이며, 수동 플레이 확인을 대체하지 않는다.

### 2단계: 낙서 생성과 지형 충돌

구현 범위: 테스트 맵에서 낙서 생성, 공중 고정, 윗면 착지·아랫면 통과·옆면 차단.

- [ ] 바라보는 방향 앞에 낙서를 생성하며, 공중에서도 생성할 수 있다.
- [ ] 낙서는 생성 위치에 고정되고 아래로 떨어지지 않는다.
- [ ] 아래에서 위로 통과하고, 내려올 때 윗면에 착지한다.
- [ ] 옆면을 통과하지 않으며, 발판 위에서 다시 이동·점프할 수 있다.
- [ ] 생성 위치·겹침·경계 처리에 사용한 임시 규칙을 기록한다.

### 3단계: 지우개와 자원 사용

구현 범위: 낙서·지우개 보유 수량, 수평 투척, 낙서 삭제, 테스트용 수량 표시.

- [ ] 낙서와 지우개 사용마다 해당 수량이 1개 감소한다.
- [ ] 수량이 0이면 사용되지 않으며 음수가 되지 않는다.
- [ ] 지우개는 처음 닿은 낙서 1개만 제거한다.
- [ ] 밟고 있는 낙서가 제거되면 플레이어가 떨어진다.
- [ ] 외계인·보스를 지우거나 피해를 주지 않는 규칙을 이후 적 구현 시 확인한다.

### 4단계: 총격, 피해, 낙서 파괴

구현 범위: 플레이어 총알, 테스트 적·적 투사체, 충돌, 체력, 게임 오버, 낙서 내구도.

- [ ] 총격이 아이템 수량을 소비하지 않고 적에게 피해를 준다.
- [ ] 플레이어 총알과 적 투사체가 낙서에 막힌다.
- [ ] 정한 임시 내구도 규칙에 따라 낙서가 파괴되고, 위의 플레이어가 떨어진다.
- [ ] 피격 시 목숨이 1개 감소하며, 시작 체력 5개를 모두 잃으면 게임 오버가 된다.
- [ ] 하나의 투사체 충돌이 여러 프레임 동안 중복 피격으로 처리되지 않는다.
- [ ] 3단계의 지우개와 적·보스 간 피해 규칙을 테스트 적으로 확인한다.

### 5단계: 패링과 아이템 획득

구현 범위: 분홍·하늘색 공격, 스페이스바 입력 판정, 보상, 공중 재도약.

- [ ] 분홍색 공격 패링 시 낙서, 하늘색 공격 패링 시 지우개를 얻는다.
- [ ] 지상 첫 점프와 공중 재입력으로 패링할 수 있다.
- [ ] 공중 성공 후 다시 도약하고 다음 공격을 연속 패링할 수 있다.
- [ ] 단순 접촉·실패한 패링은 피격이며, 일반 공격은 패링되지 않는다.
- [ ] 성공한 공격 하나가 보상이나 피해를 중복 발생시키지 않는다.
- [ ] 테스트에 사용한 판정 시간·범위를 기록한다.

### 6단계: 보스 1종으로 핵심 전투 검증

구현 범위: 고정 화면, 보스 1종의 반복 패턴, 패링 보충, 낙서·지우개 활용, 처치.

- [ ] 관찰 가능한 규칙으로 공격을 반복하고 총격으로 처치할 수 있다.
- [ ] 낙서로 방어·발판을 만들고 지우개로 사격 경로를 확보하는 전투가 가능하다.
- [ ] 낙서 생성 또는 제거가 필요한 패턴을 검증한다.
- [ ] 전체 낙서 파괴 공격과 파괴 후 낙하를 테스트한다.
- [ ] 보스전 중 패링으로 자원을 보충할 수 있다.
- [ ] 자원이 부족할 때의 전투 진행 가능성을 확인하고 조정 사항을 기록한다.

### 7단계: 횡스크롤과 전체 진행 연결

구현 범위: 횡스크롤 구간, 적·아이템 배치, 보스전 전환, 상태 유지.

- [ ] 횡스크롤 구간을 진행하고 끝에서 고정 화면 보스전으로 전환한다.
- [ ] 전환 전후 체력과 보유 아이템이 같고 자동 체력 회복이 없다.
- [ ] 보스 처치 후 다음 구간으로 진행한다.
- [ ] 이전 구간의 적·투사체가 다음 구간에 잘못 남지 않는다. 낙서의 구간 전환 처리는 별도로 확정한다.

### 8단계: 나머지 콘텐츠와 아이템

구현 범위: 총 3개 스테이지, 중간 보스 2종, 최종 UFO, 방어막·연사·폭탄.

- [ ] 세 횡스크롤 구간과 각 보스전을 순서대로 진행할 수 있다.
- [ ] 맵에서 방어막·연사·폭탄을 획득하고 각각의 효과를 확인한다.
- [ ] 방어막은 공격 1회를 막은 뒤 사라진다.
- [ ] 최종 UFO는 체력 절반 이하에서 위로 이동하며 두 번째 페이즈를 시작한다.
- [ ] 최종 UFO 처치 시 추락 연출 후 클리어 상태로 전환한다.

### 9단계: 표현과 최종 점검

구현 범위: 최종 그래픽·애니메이션, UI, 사운드, 밸런스와 버그 수정.

- [ ] 연필 낙서·색연필 외계인과 패링 공격 색상을 구분할 수 있다.
- [ ] 체력과 아이템 상태를 플레이 중 확인할 수 있다.
- [ ] 첫 스테이지부터 최종 클리어까지 한 번에 플레이할 수 있다.
- [ ] 게임 오버, 연속 패링, 공중 발판 파괴, 자원 소진을 점검한다.
- [ ] 최종 조작법과 실행 방법을 README에 반영한다.

## 7. 현재 프로젝트와 작업 요청 방법

현재 파일 역할은 다음과 같다. 기능이 늘어날 때 필요한 모듈을 추가하고, 처음부터 모든 폴더를 만들지는 않는다.

```text
Project/
├─ README.md
├─ .gitignore
├─ main.py             # 실행 시작점과 게임 루프
├─ play_mode.py        # 플레이 화면의 입력·업데이트·그리기
├─ player.py           # 플레이어 동작
├─ assets/
│  ├─ images/
│  └─ sounds/
├─ docs/
│  └─ PRD.md
└─ Slides/             # 원본 기획서와 발표 자료
```

개발 요청 예시: **“docs/PRD.md의 1단계를 구현해줘. 미정인 값은 임시 값으로 기록하고 완료 조건까지 확인해줘.”**

완료 후 해당 단계 체크박스를 갱신하고, 채택한 임시 값과 변경된 규칙을 이 문서에 기록한다. 다음 요청에서 다음 단계를 진행한다. 매 단계마다 별도 PRD를 만들지 않는다.

## 8. 점진적 개발과 커밋 규칙

- 개발은 위 단계 순서에 따라 점진적으로 진행한다. 여러 단계의 기능을 한꺼번에 구현하지 않고, 요청받은 단계 범위에서 작업한다.
- 한 단계 안에서도 실행 창, 좌우 이동, 점프처럼 확인 가능한 작은 작업 단위로 나누어 코딩한다.
- 각 작업 단위는 `구현 → 동작 확인 → 커밋` 순서로 진행한다. 단계 전체가 끝날 때까지 변경을 모아두지 않고, 의미 있는 기능 추가나 버그 수정이 확인될 때마다 수시로 커밋한다.
- 커밋에는 해당 작업과 관련된 변경만 포함한다. 관계없는 작업을 하나의 커밋에 섞지 않는다.
- 커밋 메시지는 한글로 작성하고, 무엇을 구현하거나 수정했는지 구체적으로 적는다. 파일명이나 기술 용어는 필요하면 원문을 사용한다.
- 커밋 메시지 예시: `게임 창과 기본 루프 추가`, `플레이어 좌우 이동 구현`, `점프와 바닥 착지 구현`, `낙서 옆면 충돌 오류 수정`.
- 단계 완료 시 완료 조건을 확인하고 PRD 체크리스트와 임시 값 기록도 갱신한다. 실행 확인이 불가능한 경우에는 확인하지 못한 항목과 이유를 명시하고 완료로 표시하지 않는다.
- 로컬 커밋과 원격 저장소 푸시는 구분한다. 푸시는 별도 요청이 있을 때 진행한다.
