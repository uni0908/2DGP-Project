# Doodle Wars PRD

- 기준 기획서: [doodle_wars_plan.pdf](../Slides/doodle_wars_plan.pdf)
- 개발 환경: Python / pico2d
- 문서 상태: 초기 요구사항 정리
- 목적: 게임 전체 요구사항을 공유하고, 아래 개발 단계를 하나씩 구현·확인한다.

이 문서는 기획서의 확정 규칙과 미정 항목을 정리한다. 개발 단계와 완료 조건은 구현을 위해 추가한 작업 기준이다. 미정인 값은 임의로 확정하지 않는다. 프로토타입에 임시 값이 필요하면 임시 값임을 기록하고 변경하기 쉽게 관리한다.

## 1. 게임 개요

| 항목        | 요구사항                                                                              |
| ----------- | ------------------------------------------------------------------------------------- |
| 제목        | Doodle Wars                                                                           |
| 장르        | 1인용 2D 횡스크롤 액션 슈팅 / 보스전 중심 액션                                        |
| 배경        | 연필로 그린 공책 속 낙서 세계에 색연필 외계인이 침입한다.                             |
| 목표        | 총과 아이템으로 외계인을 물리치고, 세 번째 스테이지의 최종 UFO 보스를 처치한다.       |
| 시각 스타일 | 손으로 그린 듯한 연필·색연필 드로잉                                                  |
| 참고 게임   | 컵헤드의 패링 방식과 보스 공격 패턴                                                   |
| 핵심 재미   | 패링으로 자원을 얻고, 낙서와 지우개로 전투 지형을 직접 구성하며 보스 패턴을 공략한다. |

낙서는 방어물인 동시에 이동 발판이며, 자신의 사격을 방해할 수도 있다. 플레이어는 낙서를 언제 만들고 언제 지울지 판단해야 한다. 연필 낙서는 지울 수 있지만 색연필 외계인은 지울 수 없다는 시각적 규칙을 유지한다.

## 2. 전체 진행과 상태 유지

진행 순서는 `횡스크롤 1 → 보스 1 → 횡스크롤 2 → 보스 2 → 횡스크롤 3 → 최종 UFO 보스`다.

- 스테이지는 총 3개이며, 중간 보스 2종과 최종 보스 1종을 구현한다.
- 횡스크롤 구간은 왼쪽에서 오른쪽으로 진행하며, 배경과 지형은 오른쪽에서 왼쪽으로 스크롤한다.
- 각 횡스크롤 구간이 끝나면 고정 화면 보스전으로 전환한다.
- 보스전은 기본적으로 바닥과 보스만 있는 단순한 공간에서 시작한다. 플레이어가 낙서로 전장을 구성한다.
- 체력과 보유 아이템은 구간 전환 후에도 유지한다. 보스전 진입 시 체력을 자동 회복하지 않는다.
- 시작 목숨은 5개다. 목숨은 별도 재도전 횟수가 아닌 체력 단위이며, 적의 공격에 피격될 때마다 1개 감소한다.
- 목숨이 0이면 게임 오버다. 최종 UFO 보스를 처치하면 클리어한다.
- 게임 오버 후 재시작 방식과 시작·클리어 화면의 상세 구성은 미정이다.

## 3. 기능 요구사항

### 3.1 플레이어와 기본 전투

- 플레이어는 좌우로 이동하고 스페이스바로 점프한다.
- 기본 무기는 총이며, 원거리 투사체로 공격한다. 기본 총격은 아이템을 소비하지 않는다.
- A를 누르는 동안 연속 사격한다. A만 누르면 바라보는 쪽으로 수평 사격하고, A+좌우는 해당 방향으로 이동하며 수평 사격한다.
- A+위는 좌우 이동 없이 수직 위로 사격하고, A+위+좌우는 해당 방향으로 이동하며 위 45도 대각선으로 사격한다. 점프·낙하 중에도 같은 조준 규칙을 사용한다. 위 방향키만으로는 발사하지 않으며 수직 사격 중 마지막 좌우 시선은 유지한다.
- 대각선도 수평·수직과 같은 탄속을 유지하도록 방향 벡터를 정규화한다. 현재 플레이어 탄속은 650픽셀/초, 발사 간격은 0.15초인 임시 설정이다. 이동 경로와 확장 사각형의 최초 접촉으로 낙서·적 충돌을 처리하며, 위로 나간 탄환은 화면 밖에서 소멸한다.
- 패링할 수 없는 공격은 이동, 점프 또는 낙서 엄폐물로 회피한다.
- 이동 속도와 전투 수치는 프로토타입 임시 설정을 사용한다. 위에 기록한 조작키·조준 규칙은 사용자 요청으로 채택했으며, 최종 밸런스는 플레이테스트로 조정한다.

#### 추가 조정: 최대 점프 높이

- 스페이스바를 충분히 길게 누르면 기본 바닥에서 발 위치가 화면 중앙 가까이 도달하도록 한다. 짧게 누를 때 낮게 뛰는 가변 점프는 유지한다.
- 현재 화면은 960×540, 바닥 y=80이다. 초기 점프 속도를 620에서 820픽셀/초로 높이고 중력 1800픽셀/초²와 키 해제 시 상승 속도 상한 180픽셀/초는 유지한다. 최대 상승량은 약 187픽셀로, 최고점 발 위치는 y≈267이다. 최종 밸런스는 플레이테스트로 조정한다.
- 공중 패링 성공의 재도약도 같은 초기 점프 속도를 사용한다. 사용자가 실제 실행으로 변경된 점프를 확인했다. 최대 높이와 하강 중 키 해제 동작에 대한 회귀 검사를 추가·조정했다.

#### 추가 조작: 웅크리기

사용자 요청으로 아래 방향키를 누르는 동안 웅크리는 동작을 추가한다. 다음 세부 수치는 임시 설정이다.

- 지상에서 높이를 56 → 28픽셀로 줄이고 발 위치는 유지한다. 충돌·피격·그리기 모두 현재 높이를 사용한다.
- 웅크린 이동 속도는 130픽셀/초로 기본의 절반이며, 웅크리는 동안 점프는 하지 않는다.
- 공중에서 아래를 눌러도 즉시 자세를 바꾸지 않고, 착지 후 누르고 있으면 웅크린다. 발판에서 떨어지면 현재 자세로 낙하한다.
- 아래 키를 떼거나 포커스를 잃으면 일어나기를 시도한다. 서 있는 몸이 낙서와 겹치면 웅크림을 유지하고, 공간이 확보되면 자동으로 일어난다.
- 사격·지우개 총구는 낮아진 중심 높이를 따른다. 낙서 중심이 바닥 아래로 내려가는 경우에는 바닥에 맞게 생성 높이를 올려 웅크린 상태에서도 생성할 수 있다.
- 총 29개 회귀 테스트 통과. 발 위치 유지, 키 해제, 높은 탄환 회피와 낮은 탄환 피격, 낮은 천장 아래 일어나기 방지, 이동 속도·점프 제한, 착지 후 자세를 확인했다.
- 실제 SDL 아래키 입력·해제로 웅크리기·복귀, 웅크린 낙서 생성, 렌더링·종료를 확인했다. 적 총알도 충분히 낮으면 맞으므로 모든 공격을 피하는 동작은 아니다.

### 3.2 패링

- 패링 가능한 공격의 타이밍에 맞춰 스페이스바를 입력하면 공격을 방어하고 대응 아이템을 얻는다.
- 지상의 첫 스페이스바 입력은 점프만 한다. 짧게 누르면 낮게, 길게 누르면 높게 뛰고, 공중에서 키를 떼었다 다시 누를 때만 짧은 패링 판정을 활성화한다.
- 패링 판정은 덤블링의 그림이나 발 위치에 의존하지 않고 기존 몸통 주변 범위를 사용한다. 사용자 요청으로 시도 중에는 0.16초의 공중제비와 별도 분홍색 잔상을 표시하고, 성공 시에는 성공 반동과 섬광으로 전환한다. 시도만으로 추가 도약하지 않으며 성공했을 때만 기존 재도약 물리를 적용한다.
- 공중 패링 성공 시 다시 도약한다. 이후 다른 패링 가능한 공격에 연속 패링할 수 있다.
- 접촉만으로는 패링되지 않는다. 패링에 실패한 상태로 공격에 닿으면 피격된다.
- 분홍색 패링 공격은 낙서 아이템을, 하늘색 패링 공격은 지우개 아이템을 제공한다.
- 일반 공격은 패링할 수 없다. 공격 색상으로 패링 가능 여부와 보상 종류를 구분한다.
- 보스전에서도 패링으로 아이템을 보충할 수 있다.
- 패링 판정의 허용 시간과 판정 범위는 미정이다.

### 3.3 낙서 생성과 충돌

- 낙서 아이템을 사용하면 바라보는 방향 바로 앞에 선이 뒤엉킨 둥근 낙서 덩어리를 생성한다.
- 아래 방향키+S는 앞쪽 대신 발밑에 생성한다. 공중에서 아래키를 누르고 있어도 사용할 수 있으며, 낙하 중 새 발판을 만들어 착지할 수 있다. 생성 중심 x는 플레이어와 같고, 발과 낙서 윗면 사이에 4픽셀 간격을 둔다.
- 발밑 생성도 낙서 1개를 소모하며, 플레이어·기존 낙서와 겹치거나 바닥 아래·화면 밖이면 생성하지 않고 수량도 소모하지 않는다. 일반 바닥에서는 아래에 공간이 없어 생성되지 않는다. 낙하를 즉시 강제로 멈추지 않고 기존 발판 착지 물리로 처리한다.
- 생성 위치는 플레이어의 위치와 높이를 기준으로 한다. 점프 중에도 생성할 수 있다.
- 공중에 생성된 낙서는 중력 없이 생성 위치에 고정된다.
- 플레이어가 아래에서 위로 점프하면 낙서를 통과하고, 내려올 때 윗면에 착지한다.
- 낙서의 옆면은 막혀 있어 플레이어가 통과할 수 없다.
- 낙서는 플레이어의 총격과 적 투사체를 막는다.
- 일정 피해를 받으면 파괴된다. 보스의 특정 공격은 모든 낙서를 한 번에 파괴한다.
- 밟고 있던 낙서가 파괴되면 플레이어는 아래로 떨어진다.
- 사용 시 보유 수량이 1개 감소한다. 설치 개수 제한과 재사용 대기시간은 없다.
- 크기, 생성 거리·가능 범위, 내구도와 구체적인 피해·파괴 판정 기준은 미정이다.
- 플레이어·기존 낙서와 겹쳐 생성되는 상황 및 맵 경계의 생성 처리도 구현 전에 결정한다.

### 3.4 지우개

- `D`로 지우개 아이템을 사용하면 바라보는 방향으로 수평 투척한다.
- 아래 방향키를 누른 채 `D`를 누르면 발밑으로 수직 투척한다. 웅크림과 함께 사용할 수 있고 공중에서도 아래 투척이 가능하다.
- 단, 일반 바닥에 발이 닿은 상태에서는 아래키를 웅크리기로 해석하고 D도 바라보는 방향으로 수평 투척한다. 발판 위 또는 공중처럼 발이 바닥보다 높을 때만 아래+D로 아래 투척한다. 지상에서 지우개가 즉시 바닥에 닿아 사라지는 입력 충돌을 방지한다.
- 아래 투척도 처음 닿은 낙서 하나만 제거하고 수량 1개를 소모한다. 일반 바닥은 지울 수 없으며, 바닥에 도달하면 지우개만 소멸한다. 빗나가도 수량은 반환하지 않는다.
- 처음 닿은 낙서 1개를 제거한다.
- 사용자 요청으로 지우개가 낙서를 제거하면 사용한 플레이어의 낙서 보유량을 즉시 1개 늘려 회수한다. 수평·아래 투척 모두 적용하며 지우개는 투척 시 1개 소모한다. 빗나감·바닥 소멸·총알에 의한 낙서 파괴에는 낙서를 지급하지 않는다. 밟고 있던 낙서를 회수하면 기존처럼 낙하한다. 소멸한 지우개는 재갱신돼도 낙서를 추가 제거하거나 보상을 중복 지급하지 않는다.
- 외계인과 보스는 지울 수 없으며 피해도 주지 않는다.
- 사용 시 보유 수량이 1개 감소한다. 재사용 대기시간은 없다.
- 사격 경로를 막는 자신의 낙서를 제거하여 다시 공격할 수 있어야 한다.
- 투척 속도, 사거리, 소멸 조건은 미정이다.

추가 구현 기록: 아래 투척도 임시 속도 520픽셀/초, 최대 거리 700픽셀을 사용한다. 플레이어 중심에서 아래로 이동하며 가장 먼저 만나는 낙서만 제거한다. 총 33개 회귀 테스트에서 밟은 발판 제거·낙하, 아래 낙서의 보존, 측면 낙서 무시, 바닥 소멸과 수량 부족 처리를 확인했다.

지상 웅크림 입력 충돌 수정 후 전체 61개 회귀 테스트를 통과했다. 웅크린 좌우 수평 투척과 실제 SDL 아래키+D로 앞 낙서 제거를 확인했으며, 발판·공중 아래 투척은 유지한다.

### 3.5 아이템과 자원 관리

낙서 회수 적용 후 전체 120개 회귀 테스트를 통과했다. 좌우에서 가까운 낙서 1개만 회수, 아래 발판 회수 후 낙하, 빗나감·파괴 시 미지급, 소멸한 지우개의 중복 지급 방지를 확인했다. 횡스크롤과 보스전 모두 S/D 키 이벤트와 실제 업데이트 경로에서 낙서 10→9→10 및 지우개 10→9를 확인했다.

| 아이템       | 획득 방법                 | 효과                                                      |
| ------------ | ------------------------- | --------------------------------------------------------- |
| 낙서         | 분홍색 공격 패링 성공, 지우개 제거 성공 시 회수 | 낙서 지형 생성                                            |
| 지우개       | 하늘색 공격 패링 성공     | 처음 닿은 낙서 1개 제거                                   |
| 1회용 방어막 | 횡스크롤 맵에서 직접 획득 | 플레이어를 감싸는 원이 생성되며, 공격을 1회 막으면 사라짐 |
| 연사         | 횡스크롤 맵에서 직접 획득 | 기본 총의 발사 속도 증가                                  |
| 폭탄         | 횡스크롤 맵에서 직접 획득 | 발사하면 직선으로 날아가는 공격 아이템                    |

- 횡스크롤 구간에서 확보한 자원은 보스전까지 이어진다.
- 플레이어는 회피와 패링 중 무엇을 택할지, 보유 자원을 언제 사용할지 판단한다.
- 보유 수량이 없는 아이템은 사용할 수 없고, 수량은 음수가 되지 않는다. 이는 구현 시 적용할 기본 자원 보호 조건이다.
- 초기 보유 수량, 획득당 지급 수량과 최대 보유량은 미정이다.
- 연사의 지속시간·중첩 여부, 폭탄의 피해량·폭발 범위·보유량은 추후 확정한다.
- 방어막 중복 획득과 구간 전환 시 일시 효과 유지 여부는 미정이다.

### 3.6 일반 적과 횡스크롤 구간

- 일반 적과 공격을 배치하고, 플레이어가 총격으로 적을 처치할 수 있게 한다.
- 일반 공격과 패링 가능한 공격을 구분한다.
- 구간 중 아이템을 획득하고 체력을 보존하는 과정이 이후 보스전 난이도에 영향을 준다.
- 모든 적은 몸에 접촉하면 플레이어에게 피해를 준다.
- 횡스크롤에서는 낙서·지우개를 획득하고 보유할 수 있지만 사용할 수 없다. 낙서 생성과 지우개 투척은 보스전에서만 허용한다. 횡스크롤에서 확보한 수량은 보스전으로 이어진다.

#### 일반 적 3종 설계

- **문어 외계인:** 플레이어 위치를 기준으로 현재 화면 안의 등장 구역에서 x를 무작위로 정한다. 화면 위에서 내려오며 모습을 드러내고, 바닥에 착지한 뒤 플레이어를 추적한다. 등장에는 일정한 위치 간격과 시간 간격을 두며 구체적인 간격·등장 구역·동시 등장 수는 미정이다. 추적 속도는 플레이어보다 느리고, 크기는 플레이어보다 조금 크며, 플레이어 총알 3발에 처치된다. 정확한 속도·표시 크기·충돌 크기와 하강 속도는 후속 조정한다.
- **개구리 외계인:** 플레이어보다 작고 일정 구간을 폴짝 뛰며 왕복한다. 향후 통나무 양 끝을 이동 구간으로 사용하되, 현재 통나무 지형은 미배치 상태다. 평소에는 엎드려 피격되지 않으며 플레이어가 일정 거리 안에 접근해야 총격으로 피해를 줄 수 있다. 총알 2발에 처치되고 긴 혀를 내밀어 공격한다. 접근 거리·이동 범위·공격 예고와 주기는 아래 임시 수치 기록을 따른다.
- **고양이 외계인의 폭탄 로봇:** 맵 끝에 1개 배치하고 제자리에서 대각선 위로 폭탄을 발사한다. 폭탄은 발사 순간의 플레이어 위치를 목표로 포물선을 그리며 떨어진다. 로봇은 화면 안에서 플레이어 총알 100발에 파괴된다. 화면 밖에서는 총격 피해를 받지 않는다. 폭탄 발사 주기·폭발 범위·착탄 예고는 아래 임시 수치 기록을 따른다.

일반 적 에셋은 하나씩 적용하여 화면을 확인한다. 횡스크롤의 낙서·지우개 사용 금지는 적용했다. S/D와 아래 조합으로 생성·투척하거나 수량을 소모하지 않으며, HUD는 보스전에서 사용할 수 있음을 안내한다. 기존 획득·보유·보스전 전달 경로와 보스전 S/D 사용은 유지한다. 기존 프로토타입의 횡스크롤 S/D 사용 검증 기록은 이 변경 이전의 동작을 설명한다. 그 밖의 스테이지별 배치와 세부 수치는 후속 결정한다.

#### 문어 임시 도형 구현과 접촉 피해

- 문어 최초 구현 기록: `scroll_enemy.py`의 `OctopusEnemy`와 `OctopusSpawner`를 횡스크롤에 연결했다. 당시 개구리·고양이 로봇 및 일반 적 전용 아이템 드롭은 미구현이었고 `output`의 에셋은 적용하거나 수정하지 않았다. 이후 문어 에셋 및 개구리 구현은 아래 추가 기록을 따른다.
- 첫 등장은 시작 3초 후이며 이후 3초 간격으로 등장 시도한다. 살아 있는 문어는 최대 4마리다. 현재 카메라의 좌우 64픽셀 안쪽에서 x를 무작위로 고르고, 직전 등장 위치 및 현재 문어들과 160픽셀 이상 간격을 둔다. 최대 24회 후보를 검사해 자리가 없거나 개체 수 상한이면 해당 회차를 건너뛰며 다음 회차에 몰아서 생성하지 않는다. 화면 밖으로 480픽셀 이상 멀어진 문어는 제거한다.
- 임시 도형 및 충돌 크기는 48×88이다. 화면 위 경계에 발을 두고 초당 160픽셀로 수직 하강한다. 바닥 y=144에 착지하기 전에는 수평 추적하지 않고, 착지 후 초당 110픽셀로 플레이어를 추적한다. 체력은 3이며 실제 플레이어 탄환 3발에 제거된다. 수치는 플레이 확인 후 조정할 임시 상수다.
- `game_world.update`의 공통 접촉 판정으로 살아 있는 모든 적(기존 보스 포함)의 몸에 닿으면 체력 1을 잃는다. 기존 피격 무적 시간을 공유하며 죽은 적은 접촉 피해를 주지 않는다.
- 횡스크롤에서 체력 0이면 전투·등장을 정지하고 죽기 애니메이션과 게임 오버 안내를 표시한다. 사망 상태로 보스전에 진입하지 않으며 R로 플레이어·문어·등장 타이머를 초기화한다.
- 검증: 지정한 Python 3.13 인터프리터를 샌드박스 밖에서 실행해 전체 136개 회귀 검사를 통과했다. 문어 하강·착지·추적 방향 전환, 실제 탄환 3발 처치, 등장 시간·카메라 범위·간격·상한·정리, 공통 접촉 무적, 사망 시 전투 정지·보스 진입 방지를 확인했다. 실제 SDL로 문어 하강·착지·게임 오버와 기존 보스 화면을 렌더링했고 착지 화면을 캡처하여 확인했다. 수동 조작감과 문어 에셋 적용은 후속 사용자 확인 대상이다.

#### 개구리 잠복과 왕복 점프 프로토타입

- `frog_enemy.py`에 임시 도형 개구리를 추가했다. 통나무 충돌은 아직 연결하지 않고 평지 y=144 위에서 중심 x가 680~960, 1580~1860, 2600~2880인 세 구간을 각각 왕복한다. 배치와 수치는 임시 상수이며 추후 통나무 구간으로 교체한다.
- 크기는 활성 상태 36×44, 엎드린 상태 36×16이다. 플레이어와 가로 거리 240픽셀 이내면 일어나며, 그 밖에서는 엎드려 멈춘다. 점프 중 멀어지면 현재 점프를 마치고 착지한 뒤 다시 엎드린다. 도약 중에는 피격 가능한 상태를 유지한다.
- 활성 상태에서 초당 120픽셀로 이동하고 중력 1200으로 뛴다. 최초 도약 높이 37.5픽셀은 사용자 플레이 피드백으로 80픽셀(주인공 서 있는 표시 높이)로 올렸다. `JUMP_HEIGHT = 80`에서 초기 상승 속도 약 438.18을 계산한다. 착지 후 0.4초 쉬고 다시 뛰며 구간 양 끝에서 방향을 바꾼다. 체력은 2이고 몸 접촉 피해는 기존 공통 경로를 사용한다.
- 잠복 중에는 총격 충돌 대상에서 제외하여 낮은 탄환이나 대각선 탄환도 통과한다. 활성화된 직후에는 아래의 기상 보호를 적용하며, 보호 종료 후 총알 두 발에 처치된다. 이후 개구리 에셋과 혀 공격 적용은 아래 추가 기록을 따른다.
- 검증: 잠복 중 실제 탄환 통과와 뒤쪽 대상 피격, 접근 활성화·1발 처치, 왕복 범위·반전·점프 높이, 멀어진 후 착지·잠복, 접촉 무적과 재시작을 포함해 전체 145개 회귀 검사를 통과했다.

#### 개구리 혀 공격 프로토타입

- 활성 개구리는 착지 상태에서 플레이어가 가로 180픽셀 이내이고 재사용 시간이 끝났으면 혀 공격을 시작한다. 예고 시작 시 플레이어 쪽으로 공격 방향을 고정하고 이동을 멈춘다. 임시 도형은 예고 중 황토색으로 바뀌고 입 위치를 분홍색으로 표시한다.
- 예고 0.4초 뒤 혀를 0.3초 동안 뻗기·유지·회수하며, 각각 0.1초다. 최대 길이 160·두께 8픽셀, 입 높이는 발에서 34픽셀이다. 회복 0.45초 뒤 왕복 행동으로 돌아가고 이후 1.4초간 재사용을 기다린다. 첫 공격은 활성화 전부터 흐르는 초기 대기시간 0.7초 이후 가능하다. 모든 수치는 임시 상수다.
- 혀 접촉은 피해 1이며 몸 접촉·탄환과 같은 플레이어 피격 무적 시간을 공유한다. 혀는 패링 대상이 아니고 점프·수그리기 또는 사거리 밖 이동으로 피할 수 있다. 예고 이후에는 플레이어가 뒤로 넘어가도 방향을 바꾸지 않는다.
- 기상 보호 종료 후에는 예고·공격·회복 중에도 개구리가 총알 두 발에 처치된다. 처치 즉시 혀 판정도 사라진다. 이후 개구리 에셋과 죽기 연출 적용은 아래 추가 기록을 따른다.

#### 고양이 로봇 폭발 확대와 피격 깜빡임

- 로봇 피격 시 현재 대기·반동 프레임을 0.06초 간격으로 흰색과 원래 색으로 번갈아 0.24초간 표시한다. 연속 피격 시 연출 시간을 다시 시작하며 추가 무적은 부여하지 않는다. 원본 알파와 프레임·발·몸 기준점을 유지하고 흰색 텍스처는 메모리에서만 만든다. 처치 폭발은 흰색 효과 없이 원래 색으로 재생한다.
- 사용자 요청에 따라 이번 변경은 테스트·SDL 실행 검증을 생략했다. 이전 175개 검사 통과 기록은 이번 변경 전 기준이며, 이번 효과의 화면 확인은 사용자가 진행한다.
- 후속 실행 문의로 검증을 진행했다. 변경 후 전체 175개 회귀 검사를 통과했고 실제 SDL에서 초기 화면·로봇 피격 흰색 효과·시간차 중첩 폭발과 종료까지 오류 없이 실행했다. 사용자 로그의 `as& ...`는 실행 명령 앞에 문자가 붙어 Python 시작 전에 발생한 PowerShell 문법 오류로 확인했으며 해당 문의로 게임 코드는 수정하지 않았다.
- 후속 사용자 플레이 피드백으로 각 폭발 배율을 1.6→1.0으로 되돌리고 폭발을 3개로 늘렸다. 중심은 로봇 중심 기준 왼쪽 38·오른쪽 38·위쪽 36픽셀로 배치해 서로 겹치며, 0·0.12·0.24초에 순서대로 시작한다. 마지막 폭발까지 약 0.823초간 재생한다. 피격 깜빡임은 총 0.08초·전환 간격 0.02초로 단축하여 짧게 두 번 흰색을 표시한다.
- 재조정 검증: 전체 177개 회귀 검사 통과. 실제 SDL에서 흰색 피격·복귀와 폭발 3개 중첩·연출 종료를 실행하고 캡처로 배치를 확인했다.

### 3.7 보스

- 보스는 일정한 규칙에 따라 공격을 반복한다. 플레이어가 패턴을 관찰하고 대응법을 익힐 수 있어야 한다.
- 일부 패턴에는 낙서 생성 또는 지우개 제거가 반드시 필요하다.
- 특정 위치에서 정해진 버튼만 누르는 방식으로 공략을 강제하지 않는다.
- 보스전 중 패링 가능한 공격을 제공하여 자원 보충 기회를 만든다.
- 중간 보스 2종의 외형, 세부 패턴, 페이즈는 미정이다.
- 최종 보스는 색연필로 그려진 거대 UFO다. 보스전 시작 시 화면 오른쪽에 위치한다.
- 최종 보스의 체력이 절반 이하가 되면 위쪽으로 이동하며 두 번째 페이즈를 시작한다.
- 최종 보스 처치 시 연기를 내뿜으며 아래로 추락하는 연출을 구현한다.

아래 공격 유형은 기획서의 후보이며, 모든 보스에 전부 넣는 확정 목록은 아니다.

| 공격 후보           | 기본 구상                         | 대응 방향                       |
| ------------------- | --------------------------------- | ------------------------------- |
| 일반 탄막           | 여러 발의 투사체 발사             | 이동, 점프, 엄폐물 생성         |
| 수평 공격           | 일정 높이의 넓은 범위 공격        | 엄폐물 설치, 발판으로 높이 변경 |
| 공중 공격           | 높은 위치에서 아래쪽으로 공격     | 공중 낙서 활용, 이동 경로 변경  |
| 패링 가능 공격      | 보상별 색상의 투사체              | 패링으로 자원 보충              |
| 지형 조작 필수 공격 | 낙서 생성 또는 제거가 필요한 공격 | 낙서·지우개 사용               |
| 전체 낙서 파괴 공격 | 설치된 모든 낙서 파괴             | 자원 관리, 필요한 지형 재생성   |

패턴 수·순서·속도·피해량과 보스 체력은 프로토타입 및 플레이테스트 후 확정한다. 아이템 필수 패턴에서 자원이 부족할 때의 보충 기회와 진행 가능 여부도 검증한다.

#### 추가 보스 패턴: 방어와 반격의 전환

지우개를 전투 중 자연스럽게 사용하도록, 낙서가 방패에서 장애물로 바뀌는 상황을 만든다. 사용자와 논의해 추가한 설계이며, 6단계의 첫 보스 프로토타입에 아래 흐름을 구현했다.

1. **공격 구간:** 보스가 탄막을 발사한다. 플레이어는 낙서를 만들어 엄폐하며 공격을 막는다.
2. **휴식 구간:** 낮은 탄막의 새 발사는 멈추고, 좁은 상단 범위에서 랜덤 높이의 일반탄을 빠르게 한 발씩 발사한다. 기존 탄은 지우지 않는다. 발판 위에 머무르기보다 아래로 내려와 반격하도록 유도한다.
3. **반격 구간:** 방어에 사용한 낙서가 플레이어의 사격 경로도 막는다. 지우개로 낙서를 제거해 보스를 공격할 기회를 확보한다. 별도 약점은 없으며 모든 상태에서 몸 전체를 공격할 수 있다.
4. **반복:** 반격 시간이 끝나면 다시 공격 구간으로 전환한다. 남길 낙서와 지울 낙서, 사용 시점은 플레이어가 판단한다.

핵심은 “아까는 방패였는데 지금은 방해물”이 되는 것이다. 낙서 없이 버티거나 우회 사격하는 대응도 허용한다. 약점 노출 설계는 폐기하고, 정량 발사·상단 사격 휴식을 반복하며 항상 현재 몸 전체에 피해를 줄 수 있도록 한다. 별도 예고선·카운트다운·예고 대기는 제거하고, 향후 적 애니메이션으로 동작 전환을 표현한다. 발사량·휴식 시간·자원 보충 방식은 플레이테스트로 조정한다.

#### 추가 보스 패턴 후보: 이동 경로 확보

- 보스 공격을 피하려고 이동할 때, 플레이어가 이전에 설치한 낙서가 옆길을 막는 상황을 만든다.
- 지우개로 방해되는 낙서를 제거해 이동 경로를 확보한다.
- 피할 방향과 공격 도달을 미리 알 수 있게 예고하고, 지우개 투척·낙서 제거·이동에 필요한 시간을 확보한다. 구체적인 공격 형태와 예고 시간은 프로토타입에서 정한다.

#### 추가 보스 패턴 후보: 발판 삭제로 낙하 회피

- 보스가 플레이어가 서 있는 발판 높이를 노리는 공격을 예고한다.
- 플레이어는 `아래 방향키 + D`로 밟고 있는 낙서를 지워 아래로 떨어지며 공격을 피할 수 있다.
- 현재 구현된 아래 지우개 투척을 활용한다. 삭제 후 낙하 시간과 착지 공간을 고려하고, 일반 바닥은 지워지지 않는 규칙을 유지한다.
- 발판에서 뛰어내리는 등 다른 회피법도 검토한다. 자원이 없을 때 진행이 막히는지, 지우개 수량과 보충 기회가 적절한지도 함께 검증한다.

위 후보들은 6단계 보스 1종의 핵심 전투 검증에서 적용 가능성을 확인하고, 사용할 보스와 최종 패턴 구성은 이후 확정한다.

#### 보스2 기획 아이디어: 세로 맵의 상승·하강 전투

사용자 제안으로 보스2는 세로로 긴 맵에서 전투한다. 플레이어는 낙서 발판을 계속 만들어 올라가고, 다시 내려오는 행동을 반복한다. 보스2도 맵의 위아래를 이동한다. 보스1의 좌우 사격·엄폐 중심 전투와 다른 경험을 목표로 한다. 현재는 기획만 기록하며 맵·카메라·보스2 코드는 아직 구현하지 않는다.

기본 흐름은 아래를 프로토타입 후보로 삼는다. 구체적인 공격과 순서·수치는 아직 확정하지 않는다.

1. **상승 구간:** 보스2가 위로 이동한다. 플레이어는 공중 낙서 발판을 만들어 올라가며 따라간다. 아래쪽을 위협하는 공격으로 상승을 유도하는 방안을 검토한다.
2. **높은 곳 전투:** 보스가 일정 높이에 머무르며 플레이어에게 공격 기회를 준다.
3. **하강 구간:** 위쪽을 덮는 공격 등으로 하강을 유도한다. 발판 옆으로 내려오거나 아래 방향키+D로 발판을 지워 빠르게 낙하하는 선택을 제공한다.
4. **아래쪽 전투:** 다시 반격하고 자원을 보충할 기회를 제공한 뒤 상승 흐름으로 이어간다.

- 낙서는 상승 경로이면서 하강 시 제거할 수 있는 지형이다. 지우개는 발판 삭제와 빠른 낙하에 활용한다. 사용자 요청으로 지우개에 의한 낙서 회수 기능을 채택했으며, 제거에 성공하면 낙서를 1개 회수한다.
- 카메라는 플레이어의 높이를 따라가는 방식을 우선 검토한다. 화면 밖 보스의 방향과 화면 밖에서 들어오는 공격을 알 수 있게 표시하는 방안도 검토한다.
- 먼저 작은 세로 테스트 맵에서 낙서 생성·착지로 연속 상승하는 조작과 발판 삭제·낙하 조작이 편한지 확인한 뒤 보스2를 연결한다.
- 보스전 중 낙서·지우개를 충분히 보충할 기회가 필요하다. 자원이 부족하면 상승이나 하강 진행이 막히는지, 안전하게 다시 시도할 수 있는지 검증한다.
- 맵 높이, 카메라 추적·경계, 보스 이동 범위·속도, 상승·하강 유도 공격, 반격 시간, 자원 보충 방식·수량, 낙하 중 피격·바닥 처리와 화면 밖 공격 표현은 미정이다.
- 보스2 전용 행동은 보스1과 분리한다. 현재 보스1 구현을 이 아이디어에 맞춰 변경하지 않는다.

### 3.8 그래픽, UI, 사운드

- 주인공 체력 UI는 사용자 제공 `output/HP_bar`를 `assets/images/items/player-hp.png`로 복사해 사용한다. 횡스크롤과 보스전 모두 왼쪽 위에 얼굴과 최대 5개의 하트를 표시한다. 체력에 따라 오른쪽부터 하트를 숨기고, 체력 0에는 얼굴만 표시한다. 원본의 투명 간격에서 잘라 그리므로 하트 감소 시 얼굴과 남은 하트 위치가 고정된다. 화면 좌표로 표시하며 보스전 자원·조작 안내는 UI에 겹치지 않도록 옮겼다.

- 낙서 발판 외형은 사용자 제공 `output/item-doodle.png`의 연필 낙서를 투명화한 `assets/images/items/doodle.png`로 교체했다. 선 사이 공간도 투명하게 표시하고 88×32픽셀 발판 크기에 맞춰 그린다. 외곽 사각형과 임시 곡선 표현을 이미지로 교체하며, 체력 20·발판 충돌·탄 방어·지우개 회수 규칙은 기존 값을 사용한다.

- 보스전 배경은 모눈 종이 → 산·구름 배경 → `assets/images/boss-arena/terrain_flat_960x540.png` 순서로 합성한 뒤 게임 객체를 그린다. 모눈과 산은 기존 숲 레이어의 왼쪽 960×540 구간을 원본 배율로 사용한다. 평지 그림의 윗면에 맞춰 보스전 바닥 판정을 y=144로 올리고, 플레이어·보스·낙서·지우개·레이저의 바닥 기준에도 공통 적용한다. 화면은 960×540이며 배경은 고정한다.

#### 보스1 애니메이션 시트 적용

- 보스 휴식 4초는 `crouch_enter` 약 0.333초 → `crouch_idle` 반복 → 마지막 약 0.333초의 `crouch_exit` 순서로 재생한다. 휴식에도 서기 기준 배율을 사용하고 수그리기 프레임 하단을 바닥에 맞춰 몸 전체가 축소되는 현상을 없앴다. 휴식 중 처치 시 죽기 역시 서기 기준 배율을 사용한다. 휴식 피격 높이 84픽셀과 상단 사격 주기는 기존 규칙을 따른다.

- 적용 검증. 전체 125개 회귀 테스트에서 공격 상태 매핑·피격 중 상태 보존·처치 후 마지막 프레임 유지·패링 색상·폭발 종료를 확인했다. SDL 실제 보스전 그리기로 일반·탄막·상단·유도탄·충전·왕복 레이저·피격·죽기를 검수했고 재시작 시 효과 정리도 확인했다. 손으로 그린 프레임 사이의 세부 모양 차이와 기존 게임 발사 좌표에 대한 시각적 부착 위치는 플레이하며 추가 조정한다.

- 보스1 일반탄·일반 유도탄·왕복 레이저에 별도 이펙트 시트를 연결했다. 유도탄 그림은 이동 방향에 맞춰 회전하고 충돌 시 40픽셀 폭발 효과를 재생한다. 시트는 보스의 렌더러를 공유해 투사체마다 다시 로드하지 않는다. 효과의 프레임별 공통 영역을 사용해 중심과 표시 크기가 흔들리지 않도록 한다. 패링 가능한 분홍·하늘 투사체는 시트에 색상 변형이 없어 기존 색상 도형 표시를 유지한다. 레이저의 표시 범위는 기존 가로 범위와 두께 16픽셀에 맞춘다.
- SDL 검수에서 레이저 세 번째 셀의 아래쪽 잡픽셀이 확인돼 셀 안의 빔 영역 `(24,105)-(229,144)`만 사용한다. 일반탄은 꼬리까지 포함한 시각 너비를 충돌 너비의 1.5배로 표시하고 충돌 크기·속도는 유지한다. 공격·휴식·레이저·피격·죽기 렌더링과 장면 종료 시 효과 정리를 확인했다.

- 피격은 독립 `hit_overlay` 효과를 약 0.33초 동안 공격 몸체 위에 표시한다. 공격 상태와 진행 시간은 유지한다. 처치 시 기존처럼 보스를 전투 객체에서 제거하고 `BossDeath` 시각 객체를 별도 효과 레이어에 추가한다. 죽기는 0.8초 재생 후 마지막 프레임을 유지하고 재시작·장면 종료에 정리한다. 게임 오버 상태에서도 시각 효과의 시간은 갱신한다.

- `output/boss1-sprites-v1/`의 몸체 PNG와 JSON을 연결했다. 기존 공격 상태를 일반·탄막·상단 사격·유도탄·레이저 충전·유지·회복·대기에 매핑하며 프레임 속도는 JSON을 따른다. 충전은 1초 루프를 기존 3초 상태 동안 반복한다. 기본 프레임의 중심·하단을 기준으로 등비 배율을 계산해 패턴별 높이와 상하 이동에 맞춰 그린다. 체력 표시를 유지하고 기존 사각형 몸체·충전 도형은 애니메이션으로 교체했다. 공격 주기·피격 상자·발사 좌표는 기존 규칙을 사용한다.

- 보스 디자인은 사용자 제공 `output/boss1-sprites-v2/`의 보라색 문어로 교체했다. 보스 판정 크기는 216×168, 휴식 높이는 84픽셀이며 화면 오른쪽 여백 24픽셀에 맞춰 배치한다. 기본 외형은 새 시트의 비율을 유지해 판정 안에 맞춘다. 보스 일반탄·패링탄·유도탄의 표시 및 충돌 크기를 1.5배로 확대했다. 탄막은 높이 21픽셀, 줄 중심 간격 24픽셀로 조정했다. 일반 적과 주인공의 탄 크기는 기존 값을 사용한다. 보스 공격 속도와 체력은 기존 값을 사용한다.

#### 주인공 스프라이트 첫 적용

- v5 수그리기가 조금 작아 보인다는 피드백에 따라 수그린 정지·이동·사격 외형만 5% 확대했다. 표시 배율은 0.525이며 발 기준점을 고정하고 총구 좌표에도 같은 배율을 적용한다. 기본 서기 높이는 80픽셀, 수그리기 충돌 높이는 28픽셀이다.

- 수그리기 포즈 수정본 `output/player-sprites-v5/`를 적용했다. 새 시트의 정지·이동·수평 사격 수그리기는 서기 머리 폭과 같은 원본 약 106.19픽셀로 정규화되어 있다. 게임은 서기 높이 80픽셀의 공통 배율 0.5를 사용해 수그릴 때 머리가 커지지 않도록 표시한다. 낮은 전체 외형은 약 44~46픽셀이며, 발 기준점과 총구는 v5 JSON을 따른다. 충돌 높이는 28픽셀이다. 다른 동작은 v5에 보존된 기존 프레임을 사용한다.

- 사용자 제공 `output/player-sprites-v4/`의 여우·늑대형 캐릭터로 전체 동작과 패링 효과를 교체했다. 웅크리기와 죽기도 같은 v4 시트를 사용한다. 서 있는 원본 높이 160픽셀에 표시 높이 80픽셀을 적용해 공통 배율 0.5로 그리며, JSON의 발 기준점·총구·프레임 시간을 따른다. 충돌 크기는 서기 36×56, 웅크리기 36×28이다. 아래 v1·v2 적용 내용은 이전 기록이다.

- 쓰러지기도 사용자 제공 v2 시트의 죽기 8프레임으로 교체했다. JSON의 프레임별 시간·발 기준점을 사용하고 마지막 프레임에서 멈춘다. 게임 오버 후 플레이어 애니메이션 갱신과 좌우 반전도 적용한다. v2에서는 요청한 웅크리기 4종과 죽기만 선택해 쓰며, 그 외 동작은 기존 시트를 사용한다.

- 사용자 제공 수정본 `output/player-sprites-v2`의 웅크리기로 교체했다. 기본·수평 사격 대기 각 4프레임과 기본·수평 사격 이동 각 8프레임을 제공된 JSON의 속도·총구·발 기준점에 맞춰 사용한다. 앞서 만든 네발 자세는 이전 시안으로 보존한다. 서 있는 외형 80픽셀 배율을 공통 적용하므로 현재 v2 웅크린 외형은 약 57~61픽셀이다. 충돌 높이는 기존 28픽셀로, 그림과 판정의 높이 차이는 플레이 확인 항목이다.

- 네발 자세 첫 적용. 승인한 초안에서 낮은 대기와 수평 사격 포즈를 추출해 `output/player-crouch-v2/player-crouch.png`와 JSON으로 연결했다. 정지는 단일 포즈로 표시해 팔이 흔들리지 않게 한다. 원본 제작 코드의 머리 지름 정렬과 배율을 사용하고, 발 기준점·총구 위치를 새 그림에서 구한다. 실제 패킹 후 외형은 약 41픽셀이고 충돌 높이는 기존 28픽셀이다. 초안에서 추정한 35픽셀과 차이가 있어 플레이 확인이 필요하다. 시트 생성은 `pack-crouch.ps1`로 재현한다.
- 네발 이동은 별도 `player-crouch-walk.png`의 4프레임을 초당 8프레임으로 반복한다. 기본 이동과 수평 사격 이동을 같은 다리 단계로 구성했다. 머리 지름을 정렬하고 공통 몸 기준점 `(96, 220)`을 사용해 총을 뻗을 때 그림 전체가 옆으로 이동하는 현상을 막는다. `pack-crouch.ps1 -WithWalk`로 정지·이동 시트와 JSON을 재현한다. 좌우 반전·카메라·현재 프레임 총구를 연결했고 회귀 검사와 SDL 렌더링을 확인했다.

- 최신 웅크리기 검토안은 네발로 낮게 받친 자세다. 양 무릎과 오른손으로 몸을 지지하고 왼팔을 앞으로 들어 수평 사격한다. `output/player-crouch-v2/crouch-all-fours-preview.png`에 서기·낮은 대기·왼팔 사격의 비교 초안을 저장했다. 자연스러운 머리·팔다리 비율을 우선하며 외형 높이는 28~35픽셀 부근을 검토한다. 아직 게임 적용 전 초안으로, 정확한 배치 높이와 좌우 팔 표현·이동 프레임은 후속 확인 항목이다.

- 앞서 검토한 앉아쏴 자세는 한쪽 무릎을 바닥에 대고 반대쪽 발을 앞에 세우며 상체를 앞으로 숙이는 구상이다. 이후 네발 자세로 새 초안을 비교하고 있다. 현재 웅크린 충돌 높이는 28픽셀이며, 새 외형 적용 시 그림과 판정의 차이를 다시 검토한다. 정지 시 팔을 고정하고 이동 시 낮은 걸음과 팔 동작을 적용한다.
- `output/player-crouch-v2/crouch-low-28-preview.png`에 서기·바닥 가까이 낮춘 웅크리기·낮은 수평 사격의 대표 포즈를 저장했다. 높이 비율을 검토하는 초안이며 실제 게임의 28픽셀 배치와 이동 애니메이션 연결은 후속 작업이다.
- 후속 앉아쏴 초안은 `output/player-crouch-v2/crouch-kneeling-preview.png`다. 한쪽 무릎을 댄 대기와 수평 사격을 표현한다. 현재 그림은 서기 대비 약 75% 높이로 목표보다 높고 선이 굵은 부분도 있어, 게임 적용 전 자세 높이·선 굵기를 추가 검토한다. 이미지 하단의 기준선은 검토용 초안에 포함되어 있다.

- 웅크리기 재작화 검토. 몸통·팔다리 비율 차이에 대한 사용자 피드백으로 기본 자세 원본 `source/A.png`를 참고한 서기·웅크린 대기·웅크린 사격의 대표 포즈를 제작했다. `output/player-crouch-v2/crouch-proportion-preview.png`는 비율 검토용 초안이다. 새 그림의 선 굵기와 자세를 확인한 뒤 정지 팔 고정·이동 팔 동작을 포함한 애니메이션 제작과 게임 적용을 진행한다.

- 선 보정 후속 수정: 사용자 확인에서 몸통·팔다리가 계속 옅게 보여, RGB보다 낮은 알파가 원인임을 확인했다. 기존 약한 감마 보정 대신 어두운 선에 `1-(1-alpha)^2.8`의 불투명도 보정을 적용한다. 밝은 머리 채움과 투명 픽셀은 그대로 두고 중간 농도 차이는 유지한다. 웅크리기 24프레임과 죽기 8프레임에만 적용하며, 비교 이미지의 몸통·팔다리 농도를 재확인했다. 실플레이에서의 최종 만족도는 사용자 확인이 필요하다.

- 웅크리기 동작 연결 후속 수정. 팔 동작을 수정하는 과정에서 전신 스트립을 교환해 다리까지 바뀐 처리를 되돌렸다. 정지는 `crouch_*`, 이동은 `crouch_walk_*`를 사용한다. 새 웅크리기 그림은 기본 자세의 머리·몸통·팔·다리 길이와 연필 질감을 기준으로 제작하며, 정지 시 팔을 고정하고 이동 시 낮은 걸음과 팔 동작을 사용한다.

- 웅크리기 외형 보정: 기본·수평 조준·이동의 24프레임에 한해 기존 픽셀의 어두운 선 농도와 반투명도를 완만하게 강화했다. 머리의 밝은 채움, 투명 배경, 연필 질감의 농도 차이, 프레임 좌표·크기·발/총구 기준점은 유지한다. `refine-lines.ps1`에서 원본을 기준으로 재현하며, 게임은 별도 `player-character-refined.png`를 사용한다. 원본 PNG와 JSON은 보존한다. 자세·팔다리 형태 자체를 새로 그리거나 확대하지 않는다.
- 쓰러지기 외형 보정: 죽기 8프레임에도 같은 선 농도 보정을 별도로 적용했다. 최종 보정본은 `powershell -NoProfile -ExecutionPolicy Bypass -File output/player-sprites-v1/refine-lines.ps1 -IncludeDeath`로 재현한다. 나머지 동작과 피격 프레임은 원본 그대로다. 비교 이미지에서 위는 원본, 아래는 보정본이다. 선 보정은 자세 자체의 비율 차이를 고치는 작업은 아니며 실제 플레이에서 전환 인상을 추가 확인한다.

- `output/player-sprites-v1/`의 캐릭터 PNG, 패링 이펙트 PNG와 JSON을 사용한다. 팔과 몸은 분리하지 않은 통짜 프레임이며, 오른쪽 원본을 좌우 반전해 왼쪽을 표시한다.
- `player_sprite.py`에서 대기·달리기·상승·낙하의 기본/조준 자세, 웅크리기·웅크린 이동, 피격, 죽기, 패링 시도·성공을 선택한다. 프레임 시간과 반복 여부는 JSON을 따른다. 초기의 사격 후 0.05초 전신 반동 포즈 교체는 연사 중 깜빡임으로 보여 제거했다. 발사 시에도 기본 사격 애니메이션의 재생 시간을 유지하고, 총구도 현재 기본 프레임에서 구한다. 반동 원본 자료는 보존하되 게임에서는 사용하지 않는다. 피격 무적 깜빡임은 유지한다.
- 새 숲 시안에 맞춰 사용자 요청으로 기본 서 있는 외형 높이를 64에서 80픽셀로 조정했다. `player_sprite.py`의 `DISPLAY_HEIGHT = 80`과 원본 기준 높이 145로 동일 배율 약 0.5517을 계산하며, 이미지·총구·패링 효과에 공통 적용한다. JSON의 제작 당시 권장 배율보다 게임의 표시 높이를 우선한다. 프레임별 발 기준점을 플레이어 하단에 맞추고, 카메라 이동은 그릴 때만 적용한다. 충돌 크기 36×56 및 웅크리기 36×28과 이동·점프·패링 판정은 유지한다.
- 탄환은 JSON의 총구 좌표를 좌우 반전·확대축소해 생성한다. 총구 정보가 없는 피격·패링 자세 및 위 조준 웅크림은 기존 발사 위치를 사용한다. 위 조준 웅크림 전용 그림은 없으므로 웅크린 수평 자세를 표시하며, 해당 조합의 외형은 후속 조정 항목이다.
- 피격은 0.125초 동작과 기존 무적 깜빡임을 사용한다. 죽기는 반복 없이 마지막 프레임에 멈추며, 보스전 게임 오버 후에도 플레이어 애니메이션만 계속 갱신한다.
- 생성 시트의 선 농도·팔다리 비율 차이와 자동 추정 총구 위치는 실제 플레이에서 추가 조정한다. 모든 그래픽·밸런스가 완료된 것으로 처리하지 않는다.
- 검증: 상태 선택·반전·발/총구 기준점·패링 효과·게임 오버 후 죽기 완료를 포함한 회귀 테스트와 SDL 오프스크린 렌더링으로 22개 기본 동작·반전·패링 효과의 로딩과 그리기를 확인했다. 실제 사용자 입력에 따른 체감과 프레임 연결은 후속 플레이 확인이 필요하다.

- 연필 낙서와 색연필 외계인의 차이를 시각적으로 유지한다.
- 애니메이션 프레임을 최소화하고, 반복 배경과 코드 기반 움직임을 적극 활용한다.
- 개발용 UI에는 남은 체력과 낙서·지우개 수량을 표시하여 상태를 확인할 수 있게 한다.
- 최종 UI의 배치, 보스 체력 표시, 효과음·배경음악 목록은 별도 확정한다.
- 기능 검증 단계에서는 임시 도형·이미지를 사용할 수 있다. 이는 개발 편의를 위한 방식이며 최종 그래픽 요구사항을 대체하지 않는다.

## 4. 단계별 구현과 완료 조건

각 단계는 이전 단계가 동작하는 상태에서 진행한다. 아래 체크박스는 아직 구현 완료를 뜻하지 않는다. 단계마다 완료 조건을 확인한 뒤 체크한다.

### 1단계: 실행, 이동, 점프

구현 범위: pico2d 창, 게임 루프, 입력 처리, 플레이어 좌우 이동, 점프, 바닥 충돌.

- [X] `main.py`로 창이 열리고 종료 입력으로 정상 종료한다.
- [X] 좌우 이동과 점프가 가능하며, 착지 후 다시 점프할 수 있다.
- [X] 플레이어가 바닥을 뚫지 않고, 좌우 입력 해제 시 이동이 멈춘다.
- [X] 기본 게임 진행에는 `game_framework.py`를 추가하지 않고 현재 구조를 사용한다.

#### 1단계 임시 설정과 검증 기록

- 물리 키보드 조작감과 최종 그래픽은 미검증이다. 위 완료 표시는 실제 SDL 실행 및 자동 입력·상태 검증 기준이며, 수동 플레이 확인을 대체하지 않는다.

### 2단계: 낙서 생성과 지형 충돌

구현 범위: 테스트 맵에서 낙서 생성, 공중 고정, 윗면 착지·아랫면 통과·옆면 차단.

- [X] 낙서는 생성 위치에 고정되고 아래로 떨어지지 않는다.
- [X] 아래에서 위로 통과하고, 내려올 때 윗면에 착지한다.
- [X] 옆면을 통과하지 않으며, 발판 위에서 다시 이동·점프할 수 있다.
- [X] 생성 위치·겹침·경계 처리에 사용한 임시 규칙을 기록한다.

#### 2단계 임시 설정과 검증 기록

| 항목      | 임시 설정                                                                 |
| --------- | ------------------------------------------------------------------------- |

- `game_world.py`는 지형과 플레이어를 레이어별로 등록하고 업데이트·그리기·정리를 담당한다. `Doodle` 클래스는 생성 위치를 고정 유지하며, `Player`가 지형 경계를 조회해 충돌을 처리한다.

- [X] 수량이 0이면 사용되지 않으며 음수가 되지 않는다.
- [X] 지우개는 처음 닿은 낙서 1개만 제거한다.
- [X] 밟고 있는 낙서가 제거되면 플레이어가 떨어진다.
- [ ] 외계인·보스를 지우거나 피해를 주지 않는 규칙을 이후 적 구현 시 확인한다.

#### 5단계 임시 설정과 검증 기록

이번 검증에서는 4단계의 테스트 적 상하 이동을 끄고 발사 속도를 낮췄다. 앞 단계의 수치는 당시 검증 기록이며, 현재 테스트 설정은 아래를 따른다. 정식 보스 행동은 6단계에서 설계한다.

- 테스트 적은 오른쪽 x=864, 중심 y=170에 고정한다. 크기 144 × 112와 체력 30은 유지한다.

- 가변 점프: 스페이스바를 유지하면 초기 속도 620픽셀/초와 중력 1800픽셀/초²로 최대 약 107픽셀 상승한다. 상승 중 키를 놓으면 남은 상승 속도를 최대 180픽셀/초로 제한한다. 0.016초 뒤 놓는 짧은 점프는 약 19픽셀 상승한다. 더 늦게 놓을수록 높이 뛰며, 하강 중 해제로 다시 상승하지 않는다.
- 일반탄은 주황색 12 × 6픽셀, 패링 가능 탄은 분홍·하늘색 20 × 14픽셀로 표시한다. 발사 순서는 재시작하면 일반탄부터 초기화한다.

- 활성 시간 안에 색상 탄이 들어오면 패링한다. 실패한 공중 재입력 자체는 상승 속도를 늘리지 않으며, 일반 더블 점프는 없다. 계속 누르고 있거나 OS 반복 입력이 와도 시간을 갱신하지 않는다.

- 성공한 탄은 피해 없이 소멸하고, 플레이어의 수직 속도를 620픽셀/초로 재설정해 도약한다. 이 성공 도약은 키를 떼어도 짧아지지 않는다. 한 번의 입력은 탄환 하나만 패링하고 판정을 닫으며, 연속 성공에는 재입력이 필요하다.

#### 보스1 공격 명칭과 패턴 구성

현재 제작 중인 적은 **보스1**이다. 첫 공격은 **일반 공격**이며, 나머지 세 공격은 순서를 섞는다. 이후 네 공격을 한 번씩 사용하는 묶음을 매번 섞고, 묶음 경계에서도 같은 공격이 연속되지 않도록 한다. 각 패턴은 휴식·대기·회복까지 완료한 뒤 다음으로 전환한다. 기존 탄은 유지한다. 자원 부족·밸런스 검증은 남아 있으므로 6단계 전체 완료는 아니다.

1. **탄막 공격:** 다층 낙서 방어 → 낮아진 보스와 상단 사격 휴식 → 낙서 제거 후 반격. 구현.
2. **일반 공격:** 상하 왕복 중 일반탄 3발 → 멈춤 → 패링탄 단독 발사 → 회피·도약 여유 시간. 구현.
3. **유도탄 공격:** 일반 유도탄을 낙서로 막은 뒤 단독 패링 유도탄에 대응한다. 구현.
4. **레이저 공격:** 얇은 가로 레이저가 아래→위→아래로 화면 대부분을 쓴다. 낙서는 피해 없이 통과하며, 플레이어 접촉은 피격이다. 지우개로 발판 삭제 시점을 직접 선택한다. 구현.

별도 후보였던 패링 탄 연속 발사는 일반 공격의 단독 패링탄으로 통합했다. 기존 바닥 쓸기·발판 높이 저격은 현재 네 패턴에 포함하지 않는 미구현 후보로 남겨둔다.

현재 1번은 `0.45초 간격으로 6묶음 발사 → 랜덤 상단 단발을 쏘는 휴식 4초 → 공격`을 반복하며, 시작부터 별도 예고 대기 없이 공격한다. 공격 구간은 묶음당 6발로 총 36발을 쏘고, 마지막 발사 후 간격을 포함해 2.7초다. 휴식의 상단 사격은 별도다. 수치는 모두 임시 값이다. 향후 네 패턴을 1→2→3→4 순서로 연결하는 것을 기본안으로 삼는다.

- `boss1.py`의 `Boss1`이 보스1 전용 상태와 전환을 관리한다. `boss.py`의 `Boss`는 기존 참조의 호환 이름이다. 플레이 화면은 `Boss1`을 직접 생성하며, 다른 보스에 이 패턴을 자동 적용하지 않는다. 기존 `enemy.py`의 `TestEnemy`는 기초 테스트 적으로 남겨둔다.
- 보스는 x=864, 기본 중심 y=136, 크기 144×112, 체력 30이다. 휴식에는 발 위치 y=80을 유지하고 높이를 절반인 56으로 줄인다. 표시·실제 피격 범위 모두 y=80~136이 되며, 위에 올라가 쏘면 낮아진 몸을 빗나갈 수 있다. 휴식 후에는 원래 높이로 복귀한다.
- 휴식은 웅크려 기를 모으는 모습으로 색상과 주변 테두리를 바꿔 표시한다. 약점은 없고, 항상 현재 몸 전체에 피해가 들어간다.
- 공격 중 0.45초마다 높이 y=88·104·120·136·152·168의 일반탄 6발을 발사한다. 탄속은 200픽셀/초, 각 탄 크기는 12×14픽셀이며 패링 보상은 없다. 각 탄은 처음 닿은 낙서 하나에 피해 1을 주고 사라진다.
- 세로 약 96픽셀에 걸친 탄막으로, 낙서 한 층만 세우면 서 있는 플레이어의 머리 쪽이 노출된다. 2층은 지상의 서 있는 플레이어를, 3층은 더 높은 위치까지 가리는 것을 목표로 한다. 웅크리기·이동·점프 회피를 금지하지 않으므로 모든 상황에서 3층을 강제하지는 않는다. 낙서는 점프 중 S로 높이를 달리해 쌓을 수 있으며, 기존 겹침 금지 규칙은 유지한다.
- 상태 전환과 보스 처치로 이미 발사된 탄을 강제 삭제하지 않는다. 적·아군 총알은 기존 충돌 또는 화면 이탈 조건까지 계속 움직인다. 재시작·장면 종료 시 월드 정리는 별개다. 따라서 휴식 초반에는 이전에 발사된 낮은 탄을 계속 피하거나 막아야 한다.
- 상단은 최저 높이를 유지하며 범위 폭을 절반으로 축소했다. 이전 y=152~312에서 현재 y=152~232 안의 연속 랜덤 높이를 골라 한 번에 일반탄 한 발을 발사한다. 간격도 0.08~0.14초 사이에서 랜덤으로 정하고, 탄속은 300픽셀/초다. 세로 한 줄 동시 발사·플레이어 추적·패링탄은 없다.
- 새 상단 탄의 가장 낮은 아랫면은 y=145로, 지상 플레이어 머리 y=136보다 높다. 발판 위는 계속 위협하고 지상에서는 새 상단 탄이 머리 위로 지나간다. 아래+D로 발판을 지우거나 내려온 뒤 D로 사격 경로를 열도록 유도하지만 다른 회피법도 허용한다.
- 공격·휴식 모두 현재 몸체 전체에 들어온 플레이어 총알당 피해 1을 받는다. 약점 전용 판정과 초록 약점 표시는 없다.
- 낙서는 기존처럼 양쪽 총알을 막으므로, 보스가 쉬어도 앞의 낙서를 남기면 사격이 가로막힌다. D로 제거한 뒤 A 연사로 반격할 수 있다. 우회 사격·회피도 허용하며 지우개만 정답으로 강제하지 않는다.
- 처치 시 새 사격만 멈추고 이미 발사된 탄은 계속 움직인다. 처치·게임 오버 모두 R로 다시 시작할 수 있다.
- 전체 60개 회귀 테스트에서 예고 없는 공격·상단 사격 반복, 전환 및 처치 후 낮은 탄 포함 기존 탄 보존·자연 소멸, 좁아진 랜덤 높이·연사 빈도, 지상/발판 높이 피격 차이, 다층 방어와 휴식 피격 범위를 확인했다. 실제 SDL 창에서 즉시 공격, 상단 랜덤 단발과 범위 축소, 예고 없는 렌더링·보스 자세를 검증했다.

#### 보스1 유도탄 공격 임시 설정과 검증

- 세 번째 패턴의 이름은 **유도탄 공격**이다. 보스는 오른쪽에 고정된 기본 크기로 돌아오며, 일반 유도탄 2발을 0.7초 간격으로 발사한다. 발사 구간은 1.4초다.
- 일반 유도탄은 크기 20×12픽셀, 속도 150픽셀/초, 최대 회전 속도 초당 110도다. 살아 있는 플레이어 위치를 향해 완만하게 방향을 바꾸며 즉시 방향을 꺾지 않는다.
- 유도탄에는 시간 제한과 화면 밖 이탈 소멸을 적용하지 않는다. 화면 밖으로 나가도 추적할 수 있고, 보스 처치·패턴 전환으로 강제 삭제하지 않는다. 낙서에 닿으면 내구도를 1 줄이고 소멸한다. 플레이어 피격 또는 패링 충돌은 한 번 처리한 뒤 소멸한다. 재시작·장면 종료의 월드 정리는 기존대로 적용한다.
- 일반 유도탄 2발 발사 후, 기존 적 총알·유도탄이 모두 해소될 때까지 새 탄을 쏘지 않는다. 단순히 정해진 시간만 기다리고 다음 패링탄을 겹쳐 발사하지 않는다. 유도탄이 남으면 낙서로 막거나 충돌을 해소해야 다음 단계로 진행한다.
- 주변 적 투사체가 없어진 뒤 패링 가능한 유도탄을 단독으로 한 발 발사한다. 첫 방문은 분홍(낙서 +1), 다음 방문은 하늘(지우개 +1)로 번갈아 사용한다. 크기는 24×18픽셀, 속도는 120픽셀/초, 회전 속도는 초당 90도로 일반 유도탄보다 느리다.
- 패링 유도탄이 남아 있는 동안 다른 공격을 추가하지 않는다. 패링 성공·낙서 차단·플레이어 피격으로 해소되면 1초간 새 공격 없이 기다린 뒤 레이저 준비 상태로 넘어간다. 성공 후 재도약이 다음 공격과 바로 겹치지 않도록 한다.
- 일반 유도탄은 패링 불가이며 색상 유도탄만 기존 공중 재입력 패링 규칙을 따른다. 실패하면 피격·기존 무적 규칙을 적용한다. 보상 중복 지급과 동일 탄의 중복 피해를 막는다.
- `homing_missile.py`가 2차원 추적·이동 구간 충돌을 담당한다. 대각선으로 낙서를 관통하지 않도록 선분과 확장 사각형의 최초 접촉을 계산한다.
- 전체 74개 회귀 테스트 통과. 회전 제한, 목표 추적, 시간·화면 밖 유지, 낙서 및 대각선 충돌, 두 색상 보상·일반 유도탄 피격, 기존 탄 해소 대기, 단독 패링탄, 추가 1초 여유, 방문별 색상 교대와 다음 패턴 연결을 확인했다.
- 실제 SDL 창에서 유도탄 2발이 낙서에 막힌 뒤 단독 분홍 유도탄이 나오고, 스페이스바 재입력 패링·보상·재도약·회복 후 탄막 복귀를 확인했다. 지속 추적의 회피 난이도와 자원 부족 상황은 플레이테스트로 추가 조정한다. 지우개 회수는 이번 범위에 넣지 않는다.

#### 보스1 레이저 공격 임시 설정과 검증

- 후속 조정: 충전을 1.5초에서 3초로 두 배 늘리고, 아래+S 발밑 생성 기능을 추가했다. 전체 87개 회귀 테스트에서 낙하 중 생성·고속 착지, 상승 중 생성 후 착지, 바닥·겹침 실패 시 수량 보존을 확인했다. 실제 SDL 아래키+S로 낙하 중 발판 착지와 3초 충전 후 발사를 검증했다. 레이저 전용 테스트 모드는 유지한다.

- 최신 규칙은 낙서 자동 삭제 없이 통과하는 것이다. 이전의 접촉 삭제·완전 통과 후 삭제는 폐기했다. 전체 89개 회귀 테스트에서 왕복 전후의 낙서 위치·내구도 보존, 플레이어 피격, 하강 접근 때 지우개 발판 삭제·낙하 후 회피를 확인했다. 레이저 전용 반복 모드는 유지한다.

- 현재 실행은 `play_mode.py`의 `LASER_TEST_MODE = False`로 전체 전투 모드다. 일반 공격으로 시작해 네 패턴을 중복 없는 묶음으로 섞는다. `True`로 바꾸면 레이저 전용 반복 테스트가 가능하다. 전체 94개 회귀 테스트와 실제 SDL 일반 공격 시작·R 재시작을 검증했고, 100개 난수 시드에서 묶음별 네 패턴 포함·연속 중복 방지를 확인했다. 개별 패턴의 고정 순서 회귀 검사에는 `shuffle_patterns=False`를 사용한다.

- 네 번째 패턴 이름은 **레이저 공격**이다. 가로로 긴 레이저가 화면 아래에서 위로 올라갔다가 다시 아래로 내려오고 소멸한다. 별도 수평 탄막·유도탄을 함께 발사하지 않는다.
- 두께 16픽셀로 낙서 높이 32픽셀보다 얇다. 수직 속도는 180픽셀/초로 일반 유도탄 150픽셀/초보다 조금 빠르다.
- 상승은 기존대로 레이저 중심 y=72→548이다. 하강은 y=120까지만 내려온 뒤 소멸한다. 하강 끝의 레이저 아랫면 y=112는 바닥에서 웅크린 머리 y=108보다 4픽셀 높고, 서 있는 머리 y=136보다는 낮다. 한 번 왕복에는 약 5.02초가 걸린다.
- 가로 범위는 x=48~960으로 화면의 95%다. 왼쪽 끝 48픽셀은 플레이어가 피할 수 있는 공간이다.
- 레이저는 낙서를 막힘 없이 통과하고, 낙서에 피해를 주거나 삭제하지 않는다. 발판은 레이저 통과 후에도 유지되며 ↓+D로 직접 지운 경우에만 이 동작에 의한 낙하가 일어난다. 총알에 의한 낙서 내구도·파괴 규칙은 그대로다. 레이저 접촉으로 자원을 지급하지 않으며, 직접 지우개로 제거한 낙서는 3.4절에 따라 회수한다. 지우개 자체는 소모한다.
- 낙서가 플레이어 대신 레이저 피해를 막지는 않는다. 상승 레이저를 향해 낙하하면 가로질러 맞을 수 있다. 하강 레이저 접근 전에 아래+D로 발판을 지워 내려온 뒤 바닥에서 아래키를 유지해 웅크리면, 좌우로 추가 이동하지 않고도 하강 레이저를 피할 수 있다. 서 있으면 맞는다. 자동 무적은 추가하지 않는다.
- 플레이어 접촉 시 피해 1을 주고 기존 피격 후 1초 무적을 적용한다. 레이저는 패링할 수 없다. 한 번의 업데이트에서 레이저가 지나간 세로 구간 전체를 검사해 큰 시간 간격에도 낙서를 관통해 놓치지 않는다.
- 보스는 3초 동안 청록색 몸과 수렴하는 빛 입자·테두리로 에너지를 모은다. 충전 중에는 레이저가 나오지 않는다. 공격선·카운트다운은 추가하지 않는다. 준비 뒤 레이저 한 개를 발사하고, 실제 왕복이 끝날 때까지 다음 공격을 하지 않는다. 종료 후 1초 회복 뒤 탄막 공격으로 돌아간다.
- 발사된 레이저는 보스가 처치돼도 왕복을 계속하며, 정상 왕복 완료 또는 재시작·장면 종료 시 정리된다. 상승·하강 중 새로 설치된 낙서도 보존한다.
- 하강 끝 높이 조정 후 전체 90개 회귀 테스트 통과. 실제 SDL에서도 아래+D 발판 삭제 → 제자리 낙하 → 바닥에서 웅크림 유지로 체력 5를 보존한 채 하강 레이저가 머리 위에서 끝나는 흐름을 확인했다. 낙서 보존·상승 범위·3초 충전·레이저 전용 모드는 유지한다.

- 숲 시안 적용 후 전체 120개 회귀 검사를 통과했고 SDL 실제 그리기로 캐릭터 크기·발 위치를 확인했다. 안내와 자원 표시는 검은 전경 나무에 가리지 않도록 밝은 오른쪽 위에 배치했다.

- 현재 기본 시작은 `scroll_mode.py`의 가로 3,600픽셀 맵이다. 창은 960×540, 바닥 높이는 80픽셀이다. 사용자 요청대로 바닥만 두고 적·고정 발판·이미지 에셋은 배치하지 않는다.
- 플레이어의 이동·가변 점프·웅크림·사격·낙서·지우개를 유지한다. 초기에는 사각형으로 표시했으며 이후 3.8절의 주인공 스프라이트를 적용했다. 플레이어와 투사체·낙서는 월드 좌표를 사용하며, 그릴 때만 카메라 x를 뺀다.
- 카메라는 플레이어가 화면 가로 40% 부근에 오면 따라가고, 맵의 양 끝에서는 멈춘다. 바닥 이음새와 거리 표시로 이동을 확인할 수 있다.
- 오른쪽 끝인 플레이어 중심 x=3582에 도달하면 보스1의 고정 화면으로 자동 전환한다. 체력·낙서·지우개 수량은 유지하고, 카메라·기존 낙서·탄환·누른 키 상태는 정리한다. 보스는 일반 공격으로 시작한다.
- `game_framework.py`는 장면 진입·종료·전환과 루프를 담당하고, 전환 인자로 플레이어 상태를 전달한다. `player_actions.py`는 맵과 보스전의 낙서·지우개 동작을 공유한다.
- F1은 횡스크롤 맵, F2는 보스전으로 바로 이동하는 테스트 단축키다. 단축키 이동은 새 상태로 시작한다. 맵에서 R은 맵을 초기화한다. 실제 맵 끝 자동 전환에서만 상태를 이어받는다.
- 전체 103개 회귀 테스트를 통과했다. 실제 SDL 오른쪽 입력으로 맵을 끝까지 이동해 카메라 스크롤·보스 자동 진입·체력/수량 유지·F1 맵 복귀를 확인하고 캡처 화면도 검토했다.
- 주인공 이미지는 3.8절과 같이 첫 적용했다. 적·아이템 배치와 보스 처치 후 다음 구간 연결은 아직 구현하지 않았다. 7단계 전체 완료는 아니다.

## 7. 현재 프로젝트와 작업 요청 방법

현재 파일 역할은 다음과 같다. 기능이 늘어날 때 필요한 모듈을 추가하고, 처음부터 모든 폴더를 만들지는 않는다.

```text
Project/
├─ README.md
├─ .gitignore
├─ main.py             # 실행 시작점과 게임 루프
├─ play_mode.py        # 플레이 화면의 입력·업데이트·그리기
├─ player.py           # 플레이어 동작
├─ game_world.py       # 객체 등록·업데이트·그리기와 레이어 관리
├─ doodle.py           # 고정 낙서 지형과 생성 겹침 판정
├─ eraser.py           # 지우개 수평 이동·첫 낙서 충돌·소멸
├─ bullet.py           # 진영별 수평 총알·최초 충돌·피해
├─ enemy.py            # 오른쪽 상하 왕복·연사 테스트 적
├─ assets/
│  ├─ images/
│  └─ sounds/
├─ docs/
│  └─ PRD.md
└─ Slides/             # 원본 기획서와 발표 자료
```

개발 요청 예시: **“docs/PRD.md의 1단계를 구현해줘. 미정인 값은 임시 값으로 기록하고 완료 조건까지 확인해줘.”**

완료 후 해당 단계 체크박스를 갱신하고, 채택한 임시 값과 변경된 규칙을 이 문서에 기록한다. 다음 요청에서 다음 단계를 진행한다. 매 단계마다 별도 PRD를 만들지 않는다.

## 8. 점진적 개발과 커밋 규칙

- 개발은 위 단계 순서에 따라 점진적으로 진행한다. 여러 단계의 기능을 한꺼번에 구현하지 않고, 요청받은 단계 범위에서 작업한다.
- 한 단계 안에서도 실행 창, 좌우 이동, 점프처럼 확인 가능한 작은 작업 단위로 나누어 코딩한다.
- 각 작업 단위는 `구현 → 동작 확인 → 커밋` 순서로 진행한다. 단계 전체가 끝날 때까지 변경을 모아두지 않고, 의미 있는 기능 추가나 버그 수정이 확인될 때마다 수시로 커밋한다.
- 커밋에는 해당 작업과 관련된 변경만 포함한다. 관계없는 작업을 하나의 커밋에 섞지 않는다.
- 커밋 메시지는 한글로 작성하고, 무엇을 구현하거나 수정했는지 구체적으로 적는다. 파일명이나 기술 용어는 필요하면 원문을 사용한다.
- 커밋 메시지 예시: `게임 창과 기본 루프 추가`, `플레이어 좌우 이동 구현`, `점프와 바닥 착지 구현`, `낙서 옆면 충돌 오류 수정`.
- 단계 완료 시 완료 조건을 확인하고 PRD 체크리스트와 임시 값 기록도 갱신한다. 실행 확인이 불가능한 경우에는 확인하지 못한 항목과 이유를 명시하고 완료로 표시하지 않는다.
- 로컬 커밋과 원격 저장소 푸시는 구분한다. 푸시는 별도 요청이 있을 때 진행한다.
